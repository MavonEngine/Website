The engine has two game classes that share the same underlying loop: `BaseGame` (headless) and `Game` (client with rendering).

## BaseGame

`BaseGame` is the headless core used by both the server and the client. It manages:

- **Physics world** — Rapier3D `World` instance
- **Character controller** — `KinematicCharacterController` for physics-driven movement
- **Scene** — Three.js `Scene` (shared between server and client)
- **Tick rate** — Fixed update rate (default: 30 ticks/second)
- **World** — `BaseWorld` instance managing all entities
- **Active scene** — The [scene](/core-concepts/scenes) loaded with `loadScene()` (`activeScene`)

The physics world and character controller are only set when you pass a Rapier world in, see [Physics](/core-concepts/physics).

```typescript
import BaseGame from '@mavonengine/core/BaseGame'

class MyGame extends BaseGame {
  // ...
}

const game = MyGame.instance()
```

### Tick vs update

| Method | Called by | Purpose |
|--------|-----------|---------|
| `tick()` | Fixed interval (tickRate) | Physics step, networked state sync |
| `update(delta)` | Each frame / tick | Entity updates, physics simulation |

Each tick triggers `tickComplete` with how long it took in milliseconds.

### Registering update callbacks

```typescript
game.onUpdate((delta) => {
  // Called every frame/tick with delta time in seconds
})

// Unregister when no longer needed
game.unregisterOnUpdate(callback)
```

### Environment checks

```typescript
game.isDevMode()        // true when NODE_ENV !== 'production'
game.isProductionMode() // true when NODE_ENV === 'production'
```

## Game

`Game` extends `BaseGame` for the client. In addition to everything in `BaseGame`, it sets up:

- **Canvas** — `HTMLCanvasElement` the game renders to
- **UI root** — `HTMLDivElement` for overlay UI
- **Sizes** — Window size tracking with resize handling
- **Camera** — `PerspectiveCamera` with `AudioListener`, in a [camera rig](/core-concepts/vr#the-camera-rig)
- **Renderer** — three.js's `WebGPURenderer` (on WebGL 2 by default) with shadow mapping and a post-processing pipeline, see [Renderer](#renderer)
- **Resources** — Asset loader
- **InputManager** — Keyboard, mouse and [gamepad](/input#gamepads) input
- **ParticleSystem** — Particle effects
- **LoadingScreen** — Asset loading progress screen
- **Debug** — Tweakpane debug panel (activated via `#debug`)
- **Editor** — In-dev editor (dev mode only)
- **Plugins** — The [engine plugins](/tooling/plugins) set with `Game.usePlugins()`
- **Network** — `game.network`, the `NetworkManager` once one is created
- **Local player** — `game.localPlayer`, the entity this client controls, if your game sets it (used by dev tools)
- **XR** — `game.xr`, once [`enableXR()`](/core-concepts/vr) was called

```typescript
import Game from '@mavonengine/core/Game'

const game = new Game(
  sources,         // Asset[] to load on start
  physicsWorld,    // optional RAPIER.World
  renderParameters // optional WebGPURendererParameters, e.g. { forceWebGL: false }
)
// Canvas and UI are automatically appended to document.body
```

### Render loop vs tick

The render loop runs through the renderer's animation loop (`renderer.instance.setAnimationLoop`), which a [WebXR session](/core-concepts/vr) can drive too, and renders the scene and particles. The game `update(delta)` — input, physics, entities, plugins, camera — runs on the fixed tick, like on the server. So capping the frame rate never slows down the simulation:

```typescript
game.renderer.maxFps = 60 // 0 = render every frame, ignored in VR
```

What has to move every displayed frame rather than every tick goes on `beforeRender`, which gets the time since the last rendered frame. Moving the view at the 30 Hz tick on a 60 - 120 Hz display, or in a headset, makes the world judder:

```typescript
game.on('beforeRender', (delta: number) => {
  game.camera.place(behindPlayer, player.position)
})
```

[`Entity3D`](/core-concepts/entity-system#entity3d) animations advance there, so they play at the display's rate.

### Renderer

`game.renderer.instance` is three.js's `WebGPURenderer`. It runs on its WebGL 2 backend by default, which works on the same devices as before; pass `forceWebGL: false` in the render parameters to use WebGPU where the browser has it. `game.renderer.isWebGPU` says which one runs. Materials written in [TSL](https://github.com/mrdoob/three.js/wiki/Three.js-Shading-Language) (node materials, and [material graphs](/core-concepts/material-graphs)) work on both; the engine's own grass, water, rain and smoke are TSL too.

```typescript
const game = new Game(sources, physicsWorld, { forceWebGL: false, antialias: true })
```

The scene renders through a `RenderPipeline` (`game.renderer.pipeline`), which replaced the `EffectComposer`. Add post-processing with `addEffect()`: each effect gets the picture so far, starting with `game.renderer.scenePass`, and returns the new one. Adding one under a name that's taken replaces it in place; the returned function removes it.

```typescript
import { bloom } from 'three/examples/jsm/tsl/display/BloomNode.js'

const remove = game.renderer.addEffect('bloom', input => input.add(bloom(input)))
game.renderer.effectNames // ['bloom']
```

In VR the scene goes straight to the headset without the pipeline, see [Rendering in VR](/core-concepts/vr#rendering-in-vr).

For frame and GPU timings, draw calls, memory and shaders, `game.renderer.attachInspector(container?)` starts three.js's inspector, and `detachInspector()` stops it. The debug panel's *inspector* toggle and the editor's [Performance panel](/core-concepts/level-editor#layout) do the same. It replaced the three-perf panel, which [`mavonengine upgrade`](/tooling/cli#mavonengine-upgrade) removes from older projects. `game.renderer.frames` counts the frames drawn so far.

`game.clock` is a `THREE.Timer`, advanced once per rendered frame: `getDelta()` and `getElapsed()` read the same all frame long.

### Events

| Event | When |
|-------|------|
| `documentReady` | The canvas and UI root are in the document |
| `sceneLoading` / `sceneLoaded` | A scene is being / was loaded (also on reloads) |
| `editorBoot` | The level editor booted |
| `tickComplete` | A tick finished, with its duration in ms |
| `beforeRender` | Every rendered frame, before it renders, with the time since the last one in seconds |
| `xrSessionStart` / `xrSessionEnd` | A [VR session](/core-concepts/vr) started (with the `XRSession`) / ended |

## Singleton pattern

Both classes use a static `instance()` method. Call it anywhere to get the existing instance or create one on first call.

```typescript
const game = Game.instance()
// Always returns the same instance
```
