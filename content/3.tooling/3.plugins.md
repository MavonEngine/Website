An engine plugin is an npm package that adds code to the client, the game server or both, and can bring prefabs and assets. Install one with the [CLI](/tooling/cli):

```bash
npx @mavonengine/cli install my-custom-plugin
```

## Available plugins

The official plugins are listed in [`plugins.json`](https://github.com/MavonEngine/Core/blob/main/plugins.json) at the root of the MavonEngine repository:

| Plugin | Runs on | |
| --- | --- | --- |
| [`@mavonengine/http-monitoring`](/tooling/monitoring#browser-dashboard) | server | The game server dashboard in the browser |
| [`@mavonengine/chat`](/tooling/chat) | client and server | In-game text chat with rate limiting, mutes, proximity chat and an admin API |

`mavonengine plugins` prints the list, read from GitHub each time, so a new plugin shows up as soon as it is added. The same list appears, with what your project doesn't have yet, in:

- the **Plugins** tab of the [dashboard](/tooling/monitoring#terminal-dashboard), where `i` installs the selected plugin under `mavonengine dev`;
- the **Plugins** view of the [editor](/core-concepts/level-editor#server-and-plugins-views), which also shows each plugin's readme and installs any other package;
- the `available_plugins` tool of the [MCP server](/tooling/ai-assistants#plugin-tools), so an assistant can suggest a plugin instead of building what one already does.

Installing from the dashboard or the editor asks first, since a package's code runs on your machine, then adds the plugin to `mavonengine.json` and restarts the dev servers.

To list a plugin of your own, add an entry to `plugins.json`: `package` (the npm name) is required; `name`, `description`, `target`, `engine` (the supported `@mavonengine/core` range), `homepage` and `readme` (the URL of its README as Markdown) are optional.

## mavonengine.json

Enabled plugins are listed in `mavonengine.json` in the project root, next to `package.json`:

```json
{
  "plugins": {
    "my-custom-plugin": { "enabled": true, "prefabs": ["Tree"], "options": { "density": 2 } }
  }
}
```

| Field | Description |
|-------|-------------|
| `enabled` | `false` turns the plugin off without uninstalling it |
| `prefabs` | The plugin prefabs the project uses. The editor adds a prefab when you place it. Only these prefabs' assets (plus the shared ones) go into the release |
| `options` | Passed to the plugin as `ctx.options` |

The client reloads when the plugins change. Restart the game server to load a new server plugin.

## Setting up a project

Projects made with `mavonengine create` are already set up. For an existing project:

```typescript
// client: before new Game()
import Game from '@mavonengine/core/Game'
import plugins from 'virtual:mavonengine/plugins'

Game.usePlugins(plugins)
```

```typescript
// server: the directory with mavonengine.json
const server = new MyServer(logger, physicsWorld, { plugins: { root: projectRoot } })
await server.start()
```

The client's Vite config must extend `@mavonengine/core/vite.config`, which provides `virtual:mavonengine/plugins`, serves plugin assets in dev and copies them into the release.

## Writing a plugin

Add a `mavonengine` field to the plugin's `package.json`:

```json
{
  "name": "my-custom-plugin",
  "type": "module",
  "mavonengine": {
    "target": "both",
    "client": "./dist/client.js",
    "server": "./dist/server.js",
    "engine": "^0.0.22",
    "assets": {
      "dir": "./assets",
      "shared": ["textures/bark.png"],
      "prefabs": {
        "Tree": ["models/tree.glb"],
        "Rock": ["models/rock.glb"]
      }
    }
  }
}
```

- `target`: `client`, `server` or `both`. The matching entries are required.
- `assets`: paths relative to `dir` (default `assets`), served at `/plugins/<package>/<path>`. In dev all of them; in a release only the shared ones and those of used prefabs.

Each entry default-exports the plugin. Every hook gets the plugin's context last, with `package`, `options`, `game` and `logger`.

### Client

```typescript
import { defineClientPlugin } from '@mavonengine/core/Plugins/types'

export default defineClientPlugin({
  assets: ctx => [{ name: 'tree', type: 'gltfModel', path: ctx.assetUrl('models/tree.glb') }],
  setup(ctx) {
    ctx.registerPrefab({
      name: 'Tree',
      spawn: position => ({ object: new Tree(position) }),
    })
  },
  update(delta, ctx) {},
  // Dev only, when the editor boots
  editor(ctx) {
    ctx.editor.on('objectSelected', () => {})
  },
})
```

The client context also has `registerSceneObject()` to add [scene object types](/core-concepts/scenes#scene-object-types).

### Server

```typescript
import { defineServerPlugin } from '@mavonengine/core/Plugins/types'

export default defineServerPlugin({
  setup(ctx) {},
  // Runs after the server's own onHttp routes, before the game client
  http(app, ctx) {
    app.get('/api/my-plugin/status', (_req, res) => res.json({ ok: true }))
  },
  onConnection(channel, client, ctx) {},
  onDisconnect(channel, ctx) {},
  tick(delta, ctx) {},
  destroy(ctx) {},
})
```

The server context also has `server`, `projectRoot`, `registerSceneObject()`, `requireAdmin` and `adminToken`. Plugins reach the physics world through `ctx.game.physicsWorld`, see [Physics](/core-concepts/physics).

The routes a plugin registers are listed with its name on the dashboard's Routes and Plugins tabs. Say what they do with [`describeRoute()`](/networking/server#describing-routes).

### Admin routes

Guard a plugin's admin routes with `ctx.requireAdmin`, which asks for the server's [admin token](/networking/server#admin-token), instead of giving the plugin a token of its own:

```typescript
export default defineServerPlugin({
  http(app, ctx) {
    app.post('/api/my-plugin/reset', ctx.requireAdmin, (_req, res) => res.json({ reset: true }))
  },
})
```

A plugin that takes the token some other way, such as the password of a login, checks it with `ctx.adminToken.matches(candidate)`. `ctx.adminToken.configured` tells whether the server has one. The plugin never sees the token itself.

A hook that throws is logged and turned off for that plugin, and the game keeps running.
