The game server measures itself: CPU, bandwidth, tick time against the tick budget, world, physics and memory stats, connected players, recent log output and the HTTP requests it received.

## Terminal dashboard

```bash
# Local server on the default HTTP port (8050)
npx @mavonengine/cli dashboard

# Remote server with a metrics token
MAVONENGINE_METRICS_TOKEN=secret npx @mavonengine/cli dashboard --host game.example.com --port 8050

# No server needed: simulated data
npx @mavonengine/cli dashboard --sim
```

`mavonengine dev` and `mavonengine create` show the same dashboard.

| Option | Default | |
| --- | --- | --- |
| `--host <host>` | `localhost` | Server host |
| `--port <port>` | `8050` | Server HTTP port |
| `--url <url>` | | Full metrics URL, overrides `--host` and `--port` |
| `--token <token>` | `$MAVONENGINE_METRICS_TOKEN` | Metrics token |
| `--interval <ms>` | `1000` | Poll interval |
| `--theme <name>` | `dark` | `dark`, `dracula`, `nord`, `tokyoNight`, `gruvbox`, `matrix`, `monochrome`, `highContrast`, `light` |
| `--transparent` | | Let a transparent terminal background show through |
| `--sim` | | Simulated data instead of a server |

Keys: `q` quits, `r` refreshes, `o` opens the game in the browser, `1`–`4` switch between the **Overview**, **Players**, **Logs** and **HTTP** tabs.

The HTTP tab lists every request the game server received: the client files, your `onHttp` routes, geckos.io signaling and WebSocket upgrades. Query strings are left out since they can hold tokens. The game traffic itself is WebRTC and shows on the Players tab.

## Server access

The dashboard reads `GET /api/game/metrics`, `/api/game/logs` and `/api/game/requests`. Configure them on the server:

```typescript
const server = new MyServer(logger, physicsWorld, {
  httpPort: 8050,
  metrics: {
    token: process.env.METRICS_TOKEN,
    // Recent log entries kept, 0 turns the logs endpoint off
    logBufferSize: 500,
    // Recent HTTP requests kept, 0 turns the requests endpoint off
    requestLogSize: 500,
  },
})
```

- With no token, the endpoints only answer requests from localhost.
- With `NODE_ENV=production` and no token, they are turned off.
- `metrics.enabled: false` turns them off everywhere.
- The token is sent as `Authorization: Bearer <token>` or `?token=<token>`.

## Browser dashboard

The `@mavonengine/http-monitoring` plugin serves the same dashboard from the game server, behind HTTP Basic auth.

::div{class="rounded-xl overflow-hidden shadow-2xl my-6"}
![The http-monitoring Overview tab with sample data: CPU, network and tick charts, world stats, players and logs](/images/http-monitoring.png)
::

```bash
npx @mavonengine/cli install @mavonengine/http-monitoring
```

Then open `http://<your server>:8050/monitoring/`.

### Logging in

**An htpasswd file** (recommended):

```bash
htpasswd -cB .htpasswd alice
```

```json
{
  "plugins": {
    "@mavonengine/http-monitoring": { "enabled": true, "options": { "htpasswd": ".htpasswd" } }
  }
}
```

The path is relative to the project root; `MAVONENGINE_MONITORING_HTPASSWD` works too. Keep the file out of git. Changes are picked up while the server runs. Supported hashes: bcrypt, Apache MD5 (`$apr1$`) and SHA-1 (`{SHA}`).

**One user from the environment**: `MAVONENGINE_MONITORING_USER` and `MAVONENGINE_MONITORING_PASSWORD`.

**No login configured**: in development the dashboard only answers the server's own machine; in production it stays off.

Basic auth sends the password with every request, so put HTTPS in front of a public server. After 10 failed logins an address is locked out for 5 minutes.

### Options

| Option | Default | |
| --- | --- | --- |
| `path` | `/monitoring` | Where the dashboard is served. Can't be `/` |
| `htpasswd` | `$MAVONENGINE_MONITORING_HTPASSWD` | htpasswd file, relative to the project root |
| `realm` | `MavonEngine monitoring` | Shown in the browser's login prompt |
| `pollIntervalMs` | `1000` | How often the page fetches new data, at least 250 |

Without `mavonengine.json`, pass it to the server directly:

```typescript
import { createHttpMonitoring } from '@mavonengine/http-monitoring'

const server = new MyServer(logger, physicsWorld, {
  plugins: [createHttpMonitoring({ htpasswd: '/etc/mygame/monitoring.htpasswd' })],
})
```
