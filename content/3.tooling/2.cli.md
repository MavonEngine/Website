`@mavonengine/cli` provides the `mavonengine` command. It requires **Node 24** or newer.

```bash
npm install -D @mavonengine/cli
npx @mavonengine/cli --help
```

## `mavonengine create`

Creates a new project from the multiplayer template, installs its dependencies and starts it like `mavonengine dev`.

```bash
npx @mavonengine/cli create my-game
```

Asks for a name if none is given. A startup screen shows each step; then the dev script starts, the dashboard takes over as soon as the game server answers, and the game opens in the browser. It replaces `@mavonengine/create-bootstrap`, which now forwards to it.

| Option | Default | |
| --- | --- | --- |
| `--cwd <dir>` | current directory | Where to create the project directory |
| `--no-dashboard` | | Print the progress instead of showing the dashboard |
| `--port <port>` | `8050` | Game server HTTP port for the dashboard |
| `--theme <name>` | `dark` | Dashboard theme |
| `--transparent` | | Let a transparent terminal background show through |
| `--no-open` | | Don't open the game in the browser once the server is up |

## `mavonengine dev`

Runs the dev script of the project you are in and shows the [dashboard](/tooling/monitoring) for it. For the multiplayer template that starts the game server and the client together; its `npm run dev` is `mavonengine dev`.

```bash
npx @mavonengine/cli dev

# From somewhere else
npx @mavonengine/cli dev --cwd path/to/my-game
```

- Runs the project's `dev:server` script, or `dev` when there is none.
- The project root is the nearest `package.json` upwards that depends on `@mavonengine/core` and has a `dev` script, so it also works from inside `client/` or `server/`.
- The package manager comes from the lockfile (`npm`, `pnpm`, `yarn` or `bun`).
- Once the server is up, the game opens in the browser; `o` opens it again. `q` or `Ctrl-C` stops the dev script and everything it started.

Takes the same options as `create`.

## `mavonengine install`

Installs packages with the project's package manager. For each one that is a MavonEngine [plugin](/tooling/plugins), it shows where the plugin runs and which prefabs it brings, and asks whether to add it to `mavonengine.json`.

```bash
npx @mavonengine/cli install @mavonengine/http-monitoring

# Anything your package manager takes
npx @mavonengine/cli install @acme/forest@^2 file:../my-plugin --yes
```

| Option | Default | |
| --- | --- | --- |
| `--cwd <dir>` | current directory | Where to start looking for the project |
| `-y`, `--yes` | | Add plugins to `mavonengine.json` without asking |
| `--no-register` | | Only install |

## `mavonengine build`

Runs the project's `build` script, then lists what each plugin put into the release. Only the shared plugin assets and those of the prefabs listed in `mavonengine.json` are copied, so a release never ships, or requests, a file it doesn't use.

```bash
npx @mavonengine/cli build
```

## `mavonengine dashboard`

A live terminal dashboard for a running game server, see [Monitoring](/tooling/monitoring).

```bash
npx @mavonengine/cli dashboard
npx @mavonengine/cli dashboard --sim   # simulated data, no server needed
```

## `mavonengine mcp`

A Model Context Protocol server for AI assistants, see [AI Assistants](/tooling/ai-assistants).
