`InputManager` tracks keyboard, mouse, gamepad and VR controller state and provides raycasting utilities to convert screen coordinates into world positions.

```typescript
// Accessed via game.input
const input = game.input
```

### Focus

Clicking the canvas takes the focus away from whatever had it, such as a chat input, and gives it to the game's window, so keyboard input comes back to the game, also inside an embedded iframe. When the window loses focus (clicking out of an iframe, alt-tab) or the tab is hidden, every held key and mouse button is released, since their `keyup` and `mouseup` never arrive.

## Keyboard

Keys are tracked by their [KeyboardEvent.code](https://developer.mozilla.org/en-US/docs/Web/API/KeyboardEvent/code) value.

```typescript
// Check if a key is currently held down
if (input.keysPressed.has('KeyW')) {
  // W is pressed
}

if (input.keysPressed.has('Space')) {
  // Space is pressed
}
```

### Keyboard events

```typescript
input.on('keydown', (event: KeyboardEvent) => {
  console.log('pressed:', event.code)
})

input.on('keyup', (event: KeyboardEvent) => {
  console.log('released:', event.code)
})
```

## Mouse

Mouse button state is tracked by button index (0 = left, 1 = wheel, 2 = right).

```typescript
if (input.mousePressed.has(0)) {
  // Left mouse button is held
}
```

### Cursor position

The normalized cursor position in the range `[-1, 1]` on both axes:

```typescript
input.cursor // THREE.Vector2, updated every mousemove
```

## World position raycasting

Convert the cursor position into a world-space position using `getPointerWorldPosition`:

```typescript
const worldPos = input.getPointerWorldPosition()
// Returns a THREE.Vector3 | null
```

**Parameters:**

| Parameter | Type | Description |
|-----------|------|-------------|
| `except` | `Object3D[]` | Objects to exclude from raycasting |
| `only` | `Object3D[]` | Only raycast against these objects |

```typescript
// Raycast only against the terrain
const pos = input.getPointerWorldPosition(undefined, [terrain.instance])
```

## Gamepads

Xbox, PlayStation, Nintendo and generic controllers are available through `input.gamepads`, a `GamepadManager`. It is polled once per game update, before the world updates.

> Browsers only expose a controller after a button on it was pressed while the page has focus.

```typescript
import { GamepadButton } from '@mavonengine/core/GamepadManager'

const pad = input.gamepads.primary // first connected controller, or undefined

if (pad) {
  // Sticks after the deadzone, Y is positive when pushed up
  move.set(pad.leftStick.x, 0, -pad.leftStick.y)

  if (pad.justPressed(GamepadButton.South)) // A on Xbox, Cross on PlayStation
    jump()

  const throttle = pad.value(GamepadButton.RightTrigger) // 0 - 1
}

// Any connected controller
input.gamepads.isPressed(GamepadButton.Start)
input.gamepads.justPressed(GamepadButton.A)
```

### Buttons

`GamepadButton` follows the W3C standard mapping. Use the layout agnostic names (`South`, `East`, `West`, `North`, `LeftBumper`, `RightTrigger`, `DPadUp`, …) or the Xbox (`A`, `B`, `LB`, `RT`, `View`, `Menu`) and PlayStation (`Cross`, `Circle`, `L1`, `R2`, `Share`, `Options`) aliases.

### GamepadState

| Member | Description |
|--------|-------------|
| `type` | `'xbox'`, `'playstation'`, `'nintendo'` or `'generic'`, detected from the id |
| `leftStick` / `rightStick` | `Vector2` after the radial deadzone |
| `axes` | Raw axes as reported by the browser |
| `isPressed(button)` | Button is held |
| `justPressed(button)` / `justReleased(button)` | Button changed since the previous update |
| `value(button)` | Analog value, 0 - 1 (triggers) |
| `buttonLabel(button)` | Label for the controller family, e.g. `"Cross"` or `"A"` |

### Settings

```typescript
input.gamepads.stickDeadzone = 0.15   // stick input below this is ignored
input.gamepads.buttonThreshold = 0.5  // analog buttons count as pressed above this
```

### Events

```typescript
input.gamepads.on('connected', (pad) => console.log(`${pad.type} connected`))
input.gamepads.on('disconnected', (pad) => {})
input.gamepads.on('buttondown', ({ gamepad, button }) => console.log(gamepad.buttonLabel(button)))
input.gamepads.on('buttonup', ({ gamepad, button }) => {})
```

### Rumble

```typescript
await input.gamepads.vibrate(pad.index, { duration: 200, strongMagnitude: 1, weakMagnitude: 0.5 })
// Resolves to false when the controller or browser doesn't support it
```

The [level editor](/core-concepts/level-editor)'s status bar shows connected controllers with a live debug view.

## VR controllers

Once [`game.enableXR()`](/core-concepts/vr) was called, `input.xr` reads the headset's controllers, by hand, whichever slot the session gives them. It is polled with the other input every game update and has the same API as the gamepads:

```typescript
import { XRControllerButton } from '@mavonengine/core/XRInput'

const xr = game.input.xr!

// Thumbstick after the deadzone, Y is positive when pushed forward
const stick = xr.left.stick

if (xr.right.justPressed(XRControllerButton.A))
  jump()

const grip = xr.left.value(XRControllerButton.Squeeze) // 0 - 1

// Either controller
xr.isPressed(XRControllerButton.Trigger)
```

`XRControllerButton` follows the WebXR [xr-standard mapping](https://www.w3.org/TR/webxr-gamepads-module-1/#xr-standard-gamepad-mapping) that Quest, Index, Vive, Pico and Windows Mixed Reality controllers use: `Trigger`, `Squeeze`, `Touchpad`, `Thumbstick`, `Primary` / `Secondary` and the aliases `A`, `B` (right) and `X`, `Y` (left).

| `XRController` (`xr.left`, `xr.right`) | |
| --- | --- |
| `hand` / `connected` | `'left'` or `'right'`, and whether it has a controller (or tracked hand) |
| `stick` / `axes` | The thumbstick after the deadzone, and the raw axes |
| `isPressed()` / `justPressed()` / `justReleased()` / `value()` | As on a gamepad |
| `ray` / `grip` | Follow where the controller points (-Z forward) and where it's held, to attach models or held items to. Both are in the camera rig, so they move with the player |
| `setRaycaster(raycaster)` / `getWorldPosition()` | Aim a raycaster along the controller, and where it points from |
| `vibrate(intensity, duration)` | Haptics; resolves to false when the controller can't |

`xr.raycast(hand, raycaster, objects)` gives what a controller points at, nearest first. `xr.stickDeadzone` and `xr.buttonThreshold` work as on the gamepads.

```typescript
xr.on('connected', controller => console.log(`${controller.hand} controller`))
xr.on('buttondown', ({ controller, button }) => {})
// The session's primary action: a trigger pull, or a pinch with hand tracking
xr.on('select', ({ controller }) => shoot(controller))
xr.on('squeezestart', ({ controller }) => grab(controller))
```

Events: `connected` / `disconnected`, `buttondown` / `buttonup`, `selectstart` / `selectend` / `select` and `squeezestart` / `squeezeend` / `squeeze`.

`enableXR({ input })` sets how the controllers show:

| Option | Default | |
| --- | --- | --- |
| `controllerModels` | `true` | Show their 3D models, from the WebXR input profiles |
| `controllerModelsPath` | the jsdelivr CDN | Where the models load from, to self-host them |
| `rays` / `rayLength` | `true` / `5` | A pointer line out of each controller, and how far it reaches in meters |

`input: false` leaves the controllers out.
