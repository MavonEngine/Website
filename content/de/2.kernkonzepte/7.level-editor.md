## Den Editor öffnen

Der Editor steckt in `@mavonengine/editor` und wird nur in der Entwicklung geladen. Registriere ihn mit `Game.devModeHook`, bevor du das Spiel erstellst:

```typescript
import Game from '@mavonengine/core/Game'

if (import.meta.env.DEV) {
  Game.devModeHook = () => {
    import('@mavonengine/editor').then(({ default: Editor }) => Editor.registerListener())
  }
}
```

Drücke dann `.` (oder `Insert`) im Spiel. Projekte, die mit `mavonengine create` erstellt wurden, sind bereits eingerichtet.

## Das laufende Spiel bleibt

Der Editor behält die geladene Szene und die Verbindung zum Spielserver bei, sodass die anderen Spieler und alles andere, was der Server sendet, während des Bearbeitens weiter angezeigt werden.

- Der Client teilt dem Server mit, dass er den Editor geöffnet hat. Der Server entfernt seinen Spieler, zählt ihn nicht mehr als Spieler und sendet ihm **alle** Entities der Welt, nicht nur die in der Nähe eines Spielers.
- Öffnet sich der Editor, bevor das Spiel einem Server beigetreten ist, verbindet sich das Multiplayer-Template als Zuschauer, ohne eigenen Spieler.

## Layout

| Bereich | Eingebaute Panels |
|------|-----------------|
| Links | **Scene** (die Objekte der aktiven Szene, Live-Entities und ungespeicherte Änderungen), **Explorer** |
| Unten | **Network** (siehe [unten](#network-panel)), **Performance** (der Inspector von three.js: Frame- und GPU-Zeiten, Draw Calls, Speicher, Shader; er läuft nur, solange sein Tab sichtbar ist), **Assets** (geladene Modelle und Texturen, Primitive und Lichter mit Vorschaubildern; zieh eines in die Szene) |
| Rechts | **Properties** des ausgewählten Objekts |

Die Statusleiste zeigt verbundene Gamecontroller; klick auf einen, um die Controller-Debug-Ansicht mit seinen Live-Buttons und -Sticks zu öffnen. Hat der Server die Verbindung dieses Tabs abgewiesen, etwa weil sein [Auth-Plugin](/de/werkzeuge/auth) eine Anmeldung verlangt, sagt die Statusleiste das, mit dem Grund im Tooltip.

## Die Kamera bewegen

Die Viewport-Kamera funktioniert wie im Unreal-Editor. Linksklick bleibt fürs Auswählen und das Transform-Gizmo.

| Eingabe | |
|---------|---|
| Rechts ziehen | Umsehen. Solange gehalten, fliegen `W` `A` `S` `D`, `Q` / `E` gehen runter / hoch, `Shift` ist schneller und das Mausrad ändert die Fluggeschwindigkeit |
| Mitte ziehen | Schwenken |
| `Alt` + links ziehen | Um die Auswahl kreisen, oder um den Punkt, auf den du schaust |
| Mausrad | Vor / zurück fahren |
| `F` | Die Auswahl einrahmen |

Das Menü **Viewport Overlays** in der Toolbar des Viewports hat **Show Physics**, das die Collider der Physikwelt über die Szene zeichnet.

## Graphs, Server und Plugins

Die Aktivitätsleiste am linken Rand wechselt zwischen dem Szenen-Editor und drei Ansichten, die seinen Platz einnehmen. Sie werden über den Editor gelegt, Viewport und Docks behalten also ihren Zustand.

- **Graphs** bearbeitet die [Logik-Graphen](/de/kernkonzepte/logik-graphen) und [Material-Graphen](/de/kernkonzepte/material-graphen) des Projekts und zeigt die Graphen seiner Plugins schreibgeschützt. Rechtsklick fügt einen Node hinzu, Entf entfernt die Auswahl; ein Material-Graph zeigt eine Live-Vorschau über seinen Nodes. Ein Logik-Graph, der in der Szene läuft, startet bei jeder Änderung neu und lässt seine Schritte aufleuchten, während sie laufen, und **Place in scene** fügt ein Logic-Graph-Objekt dafür hinzu. Probleme mit dem Graphen stehen rechts. Speichern schreibt `graphs/<name>.graph.json`.
- **Server** listet jeden HTTP-Endpunkt des Spielservers: Methode, Pfad, woher er kommt (Engine, Spiel oder Plugin), ob er nur in der Entwicklung existiert und was er tut. Siehe [Routen beschreiben](/de/netzwerk/server#routen-beschreiben).
- **Plugins** listet die Plugins in der `mavonengine.json` des Projekts: Version, Ziel, Beschreibung, Lizenz, unterstützter Engine-Bereich und Readme, dazu die HTTP-Endpunkte und Prefabs, die von jedem stammen. Fehlende oder ungültige Plugins werden mit dem Grund aufgeführt. Darunter stehen die [verfügbaren Plugins](/de/werkzeuge/plugins#offizielle-plugins), die das Projekt noch nicht hat, jeweils mit Readme und Install-Button, sowie „Another package“, um alles andere zu installieren. Die Installation braucht `mavonengine dev` und fragt vorher nach, siehe [Plugins im laufenden Betrieb installieren](/de/werkzeuge/cli#plugins-im-laufenden-betrieb-installieren).

## Network-Panel

Das **Network**-Panel im unteren Dock zeigt den Spiel-Socket dieses Tabs und des Servers, siehe [Netzwerk-Debugging](/de/netzwerk/zustandssync#netzwerk-debugging):

- die Pakete und Netzwerk-Events des Clients oder des Servers, nach Art gefiltert, jeweils mit Payload;
- eine Zeitleiste davon;
- den Zustandsabgleich: jeder Spieler mit den Entities, die er gesendet bekommt, seinem letzten Zustandsupdate und seinem Account, wenn der Server ein [Auth-Plugin](/de/werkzeuge/auth) hat.

Hat der Server die Verbindung abgelehnt, sagt das Panel, warum.

Es schaltet außerdem ein Overlay im Viewport ein:

- **Server ghosts**: eine Drahtgitter-Box pro vernetzter Entity, dort, wo der Server sie zuletzt gemeldet hat, mit einer Linie dorthin, wo der Client sie rendert. Grüne Ghosts sind im neuesten Zustandsupdate, orange sind diesem Client bekannt, aber nicht darin enthalten, graue werden an keinen Spieler gesendet. Wähl in der Zustandsabgleich-Tabelle einen Spieler, um die Ghosts danach einzufärben, was dieser Spieler gesendet bekommt.
- **Sync radius**: ein Ring um jeden Spieler in der Sync-Distanz des Servers.

## Szenen speichern

`Ctrl+S` / `Cmd+S` speichert die aktive [Szene](/de/kernkonzepte/szenen) über den Dev-Server nach `scenes/<name>.json`. Der Spielserver beobachtet die Datei, lädt sie neu, und jeder Client bekommt die neue Map. Wenn du ein Plugin-Prefab platzierst, wird es außerdem zu den `prefabs` des Plugins in `mavonengine.json` hinzugefügt, damit seine Assets im Release mitgeliefert werden.

## Eigene Panels

Docke deine eigenen Tools neben den eingebauten Panels an. Übergib eine React-`component` oder eine `mount`-Funktion, um mit etwas anderem zu rendern:

```typescript
import Editor from '@mavonengine/editor'

Editor.registerPanel({
  id: 'my-tools',
  title: 'My tools',
  location: 'right', // 'left' | 'bottom' | 'right'
  mount(container, editor) {
    container.textContent = 'Hello from my panel'
    return () => { container.textContent = '' } // Aufräumen
  },
})
```

`registerPanel()` funktioniert vor oder nach dem Start des Editors und gibt eine Funktion zurück, die das Panel wieder entfernt. Nach dem Start machen `editor.addPanel()` und `editor.removePanel(id)` dasselbe. Plugins bekommen den Editor in ihrem `editor(ctx)`-Hook, siehe [Plugins](/de/werkzeuge/plugins).
