Ein `Game` lässt sich über [WebXR](https://immersiveweb.dev) in einem VR-Headset spielen: im Browser einer Quest oder Pico, oder in Desktop-Chrome mit einem PC-Headset (SteamVR, Quest Link). Das [Multiplayer-Template](/de/erste-schritte/installation#multiplayer) schaltet es überall ein, wo der Browser es kann.

## VR einschalten

```typescript
import Game from '@mavonengine/core/Game'
import XR from '@mavonengine/core/XR'

const game = Game.instance()

if (await XR.isSupported())
  game.enableXR() // fügt einen „Enter VR“-Button hinzu
```

`enableXR(options)` gibt das `XR`-Objekt zurück, das auch unter `game.xr` liegt. Ein weiterer Aufruf gibt dasselbe zurück.

| Option | Standard | |
| --- | --- | --- |
| `referenceSpace` | `'local-floor'` | Wo der Ursprung des Headsets liegt: auf dem Boden unter dem Spieler, oder mit `'local'` auf seiner Kopfhöhe beim Start der Session |
| `button` | `true` | Den **Enter VR**-Button von three.js zeigen. Mit `false` rufst du stattdessen `xr.enter()` aus deiner eigenen UI auf |
| `sessionInit` | | Weitere Session-Features, z. B. `{ optionalFeatures: ['hand-tracking'] }` |
| `input` | `{}` | Wie die [Controller](#controller) erscheinen, oder `false`, um Controller-Eingaben wegzulassen |
| `mirror` | `false` | Das Spiel weiter im Browserfenster zeichnen, während ein Headset spielt. Ohne zeigt das Fenster seinen letzten Frame verschwommen. Siehe [Spiegeln](#ins-browserfenster-spiegeln) |

| `XR` | |
| --- | --- |
| `XR.isSupported()` | Ob dieser Browser und dieses Gerät immersives VR können |
| `enter()` / `exit()` | Eine Session starten oder beenden. Browser starten eine nur aus einer Nutzergeste heraus, etwa einem Klick |
| `presenting` | Ob gerade eine Session ins Headset rendert |
| `session` | Die laufende `XRSession`, falls vorhanden |
| `input` / `pointer` | Die Controller (auch `game.input.xr`) und worauf sie zeigen |
| `enableLocomotion(options)` | [Fortbewegung mit dem Thumbstick](#fortbewegung) |
| `addPanel(panel)` / `removePanel(panel)` | [Panels](#panels), die in VR erscheinen |

Das Spiel löst `xrSessionStart` (mit der `XRSession`) und `xrSessionEnd` aus.

WebXR läuft nur über `https` oder `localhost`. Um den Dev-Server per USB auf einer Quest zu spielen, leite den Port weiter, damit das Headset ihn als `localhost` öffnet:

```bash
adb reverse tcp:8050 tcp:8050
# dann http://localhost:8050 im Browser der Quest öffnen
```

Ohne Headset emuliert die Chrome-Erweiterung [Immersive Web Emulator](https://chromewebstore.google.com/detail/immersive-web-emulator/cgffilbpcibhmcfbgggfhfolhkfbhmik) eines.

### Rendern in VR

Während eine Session läuft:

- bestimmt das Headset die Framerate, `renderer.maxFps` wird also ignoriert;
- wird die Szene direkt auf die beiden Augen des Headsets gerendert, an der [Render-Pipeline](/de/kernkonzepte/spielschleife#renderer) und ihren Effekten vorbei, die nur eine Ansicht rendern. `toneMapping` und `outputColorSpace` des Renderers ersetzen die Ausgabe der Pipeline;
- werden Größenänderungen übersprungen, da die Session den Framebuffer besitzt, und nach ihrem Ende nachgeholt;
- funktioniert ein umgekehrter Tiefenpuffer (`reversedDepthBuffer: true` in den Render-Parametern). Das Headset erfährt, dass die Tiefe umgekehrt ist, damit seine Reprojektion (die das Bild um die Kopfbewegung seit dem Rendern korrigiert) entfernte Geometrie nicht mit der Kopfbewegung zittern lässt;
- verwenden Renderings in ein Render-Target, etwa eine Environment-Map oder eine Spiegelung, die Kamera, die sie bekommen haben;
- bekommt die Session nur dann einen Projection-Layer der WebXR Layers API, wenn der Browser das Feature `layers` gewährt hat, sonst den WebGL-Layer. Chrome unter Windows mit SteamVR hat die API, ohne sie zu gewähren, und zeigte vorher keine Frames.

Die Frames kommen über die Animation-Loop des Renderers, die eine Session antreibt, und das Event [`beforeRender`](/de/kernkonzepte/spielschleife#events) läuft bei jedem davon.

## Das Kamera-Rig

In VR bewegt das Headset `camera.instance` relativ zu ihrem Elternobjekt, daher sitzt die Kamera jetzt in einem Rig: `camera.rig`, eine `Group` in der Szene. Bewege die Sicht des Spielers, indem du das Rig bewegst, oder mit `place()`, das auf dem Desktop und in VR gleich funktioniert:

```typescript
// Eine Third-Person-Kamera hinter dem Spieler, in jedem gerenderten Frame
game.on('beforeRender', () => {
  game.camera.place(behindPlayer, player.position)
})
```

| `Camera` | |
| --- | --- |
| `rig` | Das Elternobjekt der Kamera. Auf dem Desktop bleibt es im Ursprung, solange du es nicht bewegst, `camera.instance.position` direkt zu setzen funktioniert dort also weiter |
| `place(position, target, { turn, pinHead })` | Die Sicht an `position` setzen, mit Blick auf `target`. Auf dem Desktop bewegt und dreht es das Rig. In VR verschiebt es das Rig so, dass der Kopf des Spielers bei `position` landet, und dreht es nur um die senkrechte Achse: Wohin der Spieler schaut, bestimmt weiter das Headset. `turn: false` verschiebt nur. In VR verschiebt die eigene Kopfbewegung des Spielers (sich vorbeugen, aufstehen) die Sicht von `position` aus; `pinHead: true` hält die Sicht bei `position` und lässt den Kopf sie nur drehen, für eine Ego-Perspektive an einem Körper |
| `turn(angle)` | Die Sicht um die senkrechte Achse durch den Kopf des Spielers drehen, z. B. für eine Snap-Drehung. Positiv dreht nach links |
| `recenter()` | Den aktuellen Versatz des Headsets als den übernehmen, den `place()` ausrichtet, z. B. nachdem sich der Spieler hingesetzt hat. Passiert im ersten Frame jeder Session |
| `worldPosition` | Wo die Kamera in der Welt ist, in jedem gerenderten Frame aktualisiert |

> `camera.instance.position` ist relativ zum Rig und damit nicht mehr die Weltposition der Kamera, sobald sich das Rig bewegt. Nimm `camera.worldPosition` für Abstandsprüfungen und Shader-Uniforms: Es bleibt immer derselbe `Vector3` und kann einer Uniform also einmal übergeben werden. Die Gras- und Wasser-Prefabs, Labels, Regen und Rauch verwenden es.

Endet eine Session, wird das Rig auf den Ursprung zurückgesetzt, damit Desktop-Steuerungen, die die Kamera selbst bewegen (Orbit, Fly), dort weitermachen, wo sie waren, und die Kamera bekommt ihr eigenes Sichtfeld zurück.

Eine stufenlose Drehung der Sicht macht vielen Spielern übel. Übergib `turn: false` und drehe stattdessen in Schritten mit `camera.turn()`, wie es das Template tut.

## Controller

`game.input.xr` liest beide Controller nach Hand, mit derselben API wie [Gamepads](/de/eingabe#gamepads). Siehe [VR-Controller](/de/eingabe#vr-controller).

## Fortbewegung

`enableLocomotion()` lässt den Spieler mit einem Thumbstick gehen, relativ zu seiner Blickrichtung, und mit dem anderen drehen, indem es das Kamera-Rig in jedem gerenderten Frame bewegt:

```typescript
game.xr!.enableLocomotion({ speed: 2, turn: 'snap' })
```

| Option | Standard | |
| --- | --- | --- |
| `speed` | `2` | Gehgeschwindigkeit bei vollem Stick, in Metern pro Sekunde |
| `moveHand` / `turnHand` | `'left'` / `'right'` | Der Stick, der bewegt, und der, der dreht |
| `turn` | `'snap'` | `'snap'` dreht in Schritten bei einem Schnippen, `'smooth'` stufenlos, `false` überlässt das Drehen dem Körper des Spielers |
| `snapAngle` | 30° | Wie weit eine Snap-Drehung dreht, in Radiant |
| `turnSpeed` | 90° | Wie schnell eine stufenlose Drehung bei vollem Stick dreht, in Radiant pro Sekunde |
| `fly` | `false` | Dorthin bewegen, wohin der Kopf schaut, auch nach oben und unten, statt auf einer Ebene zu bleiben |

Es bewegt frei und geht durch Wände, was zu freiem Erkunden passt. Ein Spiel mit Physik oder eigener Spielfigur bewegt stattdessen diese und setzt die Sicht mit `camera.place()`. `getMoveDirection(stick)` gibt die Richtung eines Sticks in der Welt, relativ zur Blickrichtung des Spielers:

```typescript
import XRLocomotion from '@mavonengine/core/XRLocomotion'

// Nicht eingeschaltet: nur für die Richtung des Sticks
const locomotion = new XRLocomotion(game.camera, game.input.xr!)

const direction = locomotion.getMoveDirection(game.input.xr!.left.stick)
player.move(direction) // z. B. an den Server schicken
```

So arbeitet `VRControls.ts` im Template: Der linke Stick (oder WASD) lässt die Figur über denselben `CL_MOVE`-Befehl gehen wie die Tastatur, der Server braucht für VR also nichts, und der rechte Stick (oder Q / E) dreht die Verfolgerkamera in Schritten um sie herum.

## Labels und Panels in VR

Ein Headset zeigt nichts vom HTML der Seite, was ein Spiel in VR zeigt, muss also in der Szene sein.

### Labels

`ObjectLabel` (und `UILabel`) funktionieren weiter: Während ein Headset spielt, wird das Label statt seines HTML-Elements als `TextLabel` in die Szene gezeichnet. Standardmäßig zeigt es den Text des Elements; überschreibe `xrText()`, um festzulegen, was erscheint, Zeilen getrennt mit `\n`, oder gib `undefined` zurück, um in VR nichts zu zeigen. Überschreibe `xrLabelOptions()`, um es zu gestalten.

```typescript
class PlayerLabel extends ObjectLabel {
  protected xrText() {
    return this.chatBubble ? `${this.chatBubble}\n${this.name}` : this.name
  }
}
```

`TextLabel` lässt sich auch allein verwenden: Text auf einem Sprite, das immer zum Betrachter zeigt, unbeleuchtet und ohne Tone-Mapping und Nebel, über die Szene gezeichnet, solange `depthTest` nicht gesetzt ist.

```typescript
import TextLabel from '@mavonengine/core/ui/TextLabel'

const label = new TextLabel('Checkpoint', { angularSize: 2 })
label.position.set(0, 3, 0)
game.scene.add(label)
// Mit angularSize die Größe in jedem gerenderten Frame halten
game.on('beforeRender', () => label.update(game.camera.instance))
```

| Option | Standard | |
| --- | --- | --- |
| `font` | `'600 40px system-ui, sans-serif'` | CSS-Font, in der Größe, in der der Text auf das Canvas gezeichnet wird |
| `color` / `background` | Weiß / durchscheinendes Schwarz | `background: ''` für keinen |
| `padding` / `radius` | ein Drittel der Schrifthöhe / das halbe Padding | In Canvas-Pixeln |
| `height` | `0.25` | Seine Höhe in der Welt, in Metern |
| `angularSize` | | In jedem Abstand gleich groß erscheinen, als Winkel in Grad (2 liest sich wie 14-px-Text auf einem Monitor) |
| `depthTest` | `false` | Von der Szene davor verdeckt |

`setText()` und `setIcon()` zeichnen es nur neu, wenn sich etwas ändert.

### Panels

`XRPanel` ist eine flache Tafel mit einem Canvas darauf, für ein Menü, eine Punktetafel oder eine Nachricht. Zeichne auf ihren `ctx`, rufe `redraw()` auf und füge sie mit `xr.addPanel()` hinzu. Sie erscheint in VR, solange sie geöffnet ist, sitzt im Kamera-Rig und bewegt sich also mit dem Spieler, und die Controller zeigen mit einer Linie und einem Punkt darauf, der Trigger als Taste:

```typescript
import XRPanel from '@mavonengine/core/ui/XRPanel'

const menu = game.xr!.addPanel(new XRPanel({ width: 1, height: 0.6 }))
menu.ctx.fillStyle = '#111'
menu.ctx.fillRect(0, 0, menu.canvas.width, menu.canvas.height)
menu.ctx.fillStyle = '#fff'
menu.ctx.font = '64px system-ui'
menu.ctx.fillText('Weiter', 80, 300)
menu.redraw()

menu.on('click', ({ hand, x, y }) => {
  // x und y in Canvas-Pixeln von oben links
  if (y > 220 && y < 340)
    menu.close()
})

menu.open()
```

| Option | Standard | |
| --- | --- | --- |
| `width` / `height` | `1` / `0.6` | Ihre Größe in Metern |
| `pixelsPerMeter` | `1000` | Wie scharf das Canvas ist |
| `follow` | `'head'` | `'head'` öffnet sie vor dem Spieler und lässt sie zurückgleiten, sobald er deutlich wegschaut; `'none'` lässt `mesh` dort, wo das Spiel es hinsetzt, im Raum des Rigs |
| `distance` / `drop` | `1.5` / `0.15` | Wie weit vor dem Kopf sie schwebt und wie weit unter Augenhöhe |
| `followAngle` | `35` | Wie weit sich die Sicht in Grad abwendet, bevor sie folgt |

Panels bekommen `pointermove`, `pointerleave`, `pointerdown`, `pointerup` und `click`. `xr.pointer.pointingAt(hand)` sagt, auf welches Panel ein Controller zeigt, damit das Spiel den Trigger dem Menü überlassen kann, statt zu schießen.

## Ins Browserfenster spiegeln

Ohne Spiegel zeigt das Browserfenster, während ein Headset spielt, seinen letzten Frame verschwommen mit *Playing in VR* darüber. Die UI des Spiels bleibt obenauf. Mit `enableXR({ mirror: true })`, oder jederzeit mit `xr.mirror = true`, wird die Szene stattdessen nach jedem Headset-Frame ein weiteres Mal gezeichnet, vom Kopf des Spielers aus und im Format des Fensters auf die Seite. `mirror: { fov: 70 }` setzt ihr Sichtfeld. Das ist für Zuschauer oder einen Stream gedacht und verwendet die Shadow-Maps des Headset-Frames wieder.

Es kostet das Headset Frames: three.js baut die Render-Pipeline jedes Objekts neu, sobald die Kamera zwischen den Augen des Headsets und der des Spiegels wechselt. Eine Valve Index lief in Chrome unter Windows damit mit 45 Hz und ohne mit 90 Hz. Deshalb lässt das Template ihn aus:

```typescript
XR.isSupported().then((supported) => {
  if (supported)
    game.enableXR()
})
```
