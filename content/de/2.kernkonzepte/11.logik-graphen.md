Ein Logik-Graph ist Spiellogik aus Nodes statt aus Code: Events starten einen Durchlauf, Exec-Kanten bringen seine Schritte in eine Reihenfolge, und Wert-Nodes rechnen aus, was die Schritte brauchen. Du baust sie in der **Graphs**-Ansicht des [Level-Editors](/de/kernkonzepte/level-editor), und ein `LogicGraph`-Objekt in einer [Szene](/de/kernkonzepte/szenen) führt einen auf dem Client, dem Server oder beiden aus.

![Die Graphs-Ansicht des Level-Editors mit dem server-npc-Logik-Graphen des Multiplayer-Templates: Gruppen zum Merken des Startpunkts, Laufen, Umdrehen und Antworten auf Klicks, rechts die Parameter des Graphen](/static/logic-graph-editor.png)

## Der NPC des Templates

Das [Multiplayer-Template](/de/erste-schritte/installation#multiplayer) bringt einen mit: `graphs/server-npc.graph.json`. Ein `ServerNpc` in `scenes/main.json` ist eine vernetzte Entity, die von sich aus nichts tut. Ein `LogicGraph`-Objekt daneben führt `server-npc` auf dem Server mit dem NPC als Self aus. So lässt der Server ihn hin und her laufen, und jeder Spieler sieht ihn über den üblichen [State-Sync](/de/netzwerk/zustandssync) laufen.

```json
{
  "id": "server_npc_logic",
  "type": "LogicGraph",
  "name": "Server NPC logic",
  "transform": { "position": [0, 0, -6], "rotation": [0, 0, 0], "scale": [1, 1, 1] },
  "props": {
    "graph": "server-npc",
    "side": "server",
    "target": "server_npc"
  }
}
```

**On Tick** bewegt den NPC um `dir × speed × delta` entlang x und dreht ihn in Laufrichtung. Ein **Branch** dreht `dir` um, sobald er weiter als `range` von seinem Startpunkt entfernt ist. `dir`, `speed` und `range` sind die Parameter des Graphen.

![Die Gruppen Walk und Turn around des server-npc-Graphen: On Tick führt Move By und Set Rotation aus, dann vergleicht ein Branch die zurückgelegte Strecke mit range und dreht dir um](/static/logic-graph-walk.png)

Ein Klick auf den NPC schickt `CL_NPC_CLICK` an den Server, der ihn als Nachricht `clicked` an die Graphen weitergibt, die auf diesen NPC wirken. **On Message** empfängt sie, **Cooldown** lässt sie höchstens alle 10 Sekunden durch, und der eigene **Say in Chat**-Node des Templates schreibt als NPC eine Zeile in den Chat:

![Die Gruppe Answer clicks: On Message mit dem Namen clicked, dann Cooldown mit 10 Sekunden, dann Say in Chat mit der Begrüßung des NPCs](/static/logic-graph-clicks.png)

```typescript
// server/src/Server.ts
channel.on(ClientCommand.CL_NPC_CLICK, (command) => {
  const cmd = command as CL_NPC_CLICK
  if (this.game.world.entities.items.get(cmd.npcId) instanceof ServerNpc)
    sendGraphMessage('clicked', player.name ?? '', cmd.npcId)
})
```

## Einen Graphen in einer Szene ausführen

Ein `LogicGraph`-Szenenobjekt lädt einen Graphen und führt ihn jeden Tick aus. Füge eines mit **Place in scene** in der Graphs-Ansicht hinzu, oder in der Szenendatei:

| Prop | Standard | |
|------|----------|---|
| `graph` | | `name` für `graphs/<name>.graph.json`, `<package>:<name>` für den eines [Plugins](#graphen-aus-plugins) |
| `side` | `'client'` | Wo er läuft: `'client'`, `'server'` oder `'both'` |
| `target` | dieses Objekt | Die id des Szenenobjekts, auf das der Graph als **Self** wirkt. Ohne bewegt er sich selbst, er hat eine eigene Transformation |
| `parameters` | Standardwerte des Graphen | Werte für die Parameter des Graphen |

Der Editor zeigt ihn als Helfer im Viewport, mit Graph, Seite und Self im Properties-Panel. Ein Graph, der nur auf dem Server läuft, wird trotzdem auf dem Client gebaut, damit der Editor ihn zeigen und verschieben kann.

Der Server liest Graphen aus dem Verzeichnis `graphs/` des Projekts, gib ihm also die Option `root` (das Template tut das). Im Dev-Modus beobachtet er das Verzeichnis: Speicherst du einen Graphen im Editor, startet er in jedem Objekt auf dem Server neu, ab On Start. Ein Graph, der nicht mehr laufen kann, behält die alte Version und loggt warum. Auf dem Client macht der Editor dasselbe beim Bearbeiten, und die Schritte leuchten in der Graphs-Ansicht auf, während sie laufen.

## Nodes

Schritte haben Exec-Ports (weiß) und laufen an ihnen entlang nacheinander. Wert-Nodes haben keine: Sie werden ausgerechnet, wenn ein Schritt sie liest, für jeden Schritt neu, sodass ein Schritt sieht, was die vorherigen geändert haben. Die Ausgaben eines Schritts behalten ihren letzten Wert.

| Kategorie | Nodes |
|-----------|-------|
| Events | **On Start** (einmal), **On Tick** (jeden Tick, mit `delta`), **Every** (alle paar Sekunden), **On Key** (eine Taste nach Code, z. B. `Space`, `KeyW`; nur Client), **On Message** (eine Nachricht nach Name, mit ihrem Wert) |
| Ablauf | **Branch**, **Sequence** (Ausgänge 1, 2, 3 nacheinander), **Do Once**, **Cooldown** (frühere Durchläufe gehen nach Blocked), **Delay** |
| Aktionen | **Log** (ins Log des Spiels), **Send Message** (an jeden Logik-Graphen auf dieser Seite) |
| Entity | **Self**, **Scene Object** (nach id), **Position** / **Rotation** / **Scale**, **Set …**, **Move By** / **Rotate By** / **Grow By** |
| Variablen | **Get Variable**, **Set Variable**. Eine Variable beginnt mit dem gleichnamigen Parameter, falls es einen gibt |
| Logik | **Compare** (`<`, `<=`, `==`, `!=`, `>=`, `>`), **And**, **Or**, **Not** |
| Eingabe | **Float**, **Vec2**, **Vec3**, **Vec4**, **Color**, **Bool**, **Text**, **Parameter**, **Time** |
| Mathe, Vektor | Add, Subtract, Multiply, Divide, Min, Max, Power, Step, Sine, Cosine, Absolute, Floor, Fraction, Square Root, Negate, One Minus, Mix, Clamp, Smoothstep, Remap; Combine, Split, Length, Distance, Dot, Normalize, Cross |

Entity-Eingänge nehmen die id eines Szenenobjekts; leer bedeuten sie Self. Mathe-Nodes arbeiten mit Zahlen und Vektoren gleichermaßen, komponentenweise: ein Float und ein vec3 ergeben ein vec3.

**Comment**- und **Group**-Nodes tun nichts, wenn der Graph läuft. Ein Kommentar beschreibt einen Teil des Graphen, eine Gruppe ist ein benannter Rahmen, der die Nodes darin zusammen verschiebt.

Ein Durchlauf kann das Spiel nicht aufhängen: Ein Event führt höchstens 10 000 Schritte aus, dann loggt der Graph, dass seine Exec-Kanten wohl eine Schleife bilden.

## Nachrichten

**Send Message** erreicht jeden Logik-Graphen auf derselben Seite und dessen **On Message**-Nodes mit diesem Namen. Aus Code sendest du eine mit `sendGraphMessage()`, an jeden Graphen oder nur an die, die auf ein bestimmtes Szenenobjekt wirken:

```typescript
import { sendGraphMessage } from '@mavonengine/core/Graph/Logic/logicGraphObject'

sendGraphMessage('alarm', 1)                 // jeder Logik-Graph auf dieser Seite
sendGraphMessage('clicked', 'Alice', npc.id) // nur die Graphen, deren Self npc ist
```

Nachrichten bleiben auf ihrer Seite: Ein Client-Graph hört keinen Server-Graphen. Schick ein [Command](/de/netzwerk/client) hinüber und ruf auf der anderen Seite `sendGraphMessage()` auf, wie das Template es für Klicks macht.

## Eigene Nodes

Ein Node-Typ ist eine `NodeDefinition`: seine Ports und ein `run` für einen Schritt oder ein `eval` für einen Wert-Node. Registriere ihn auf jeder Seite, deren Graphen ihn nutzen; der Editor braucht ihn auf dem Client, um ihn anzuzeigen, auch wenn der Graph nur auf dem Server läuft. Das ist der Say-in-Chat-Node des Templates:

```typescript
import type { NodeDefinition } from '@mavonengine/core/Graph/NodeRegistry'
import { registerNode } from '@mavonengine/core/Graph/NodeRegistry'

export const sayInChatNode: NodeDefinition = {
  type: 'chat.say',
  label: 'Say in Chat',
  category: 'Actions',
  description: 'Post a line in the chat as the graph\'s Self',
  kinds: ['logic'],
  inputs: {
    run: { type: 'exec', label: '' },
    message: { type: 'any', label: 'Message', default: 'Hello!' },
  },
  outputs: {
    then: { type: 'exec', label: '' },
  },
  run: ({ message }, { self }) => {
    post?.(self?.id ?? '', String(message ?? ''))
  },
}

registerNode(sayInChatNode)
```

| Feld | |
|------|---|
| `type`, `label`, `category`, `description` | Sein Schlüssel in Graph-Dateien, und wie der Editor ihn auflistet |
| `kinds` | `['logic']`, `['material']` oder beides |
| `inputs`, `outputs` | Ports nach Name: `{ type, label?, default? }`. Typen: `float`, `int`, `bool`, `vec2`, `vec3`, `vec4`, `color`, `texture`, `string`, `entity`, `exec`, dazu `number` (jede Zahl oder jeder Vektor) und `any` |
| `settings` | Werte, die am Node selbst gesetzt statt verbunden werden |
| `eval(inputs, ctx)` | Die Ausgaben eines Wert-Nodes |
| `run(inputs, ctx)` | Ein Schritt. Gib `{ next, outputs }` zurück, um die Exec-Ausgänge zu wählen, an denen es weitergeht (standardmäßig der erste, keiner bei `[]`), und seine Ausgaben zu setzen |
| `trigger` | Macht ihn zum Event: das Runtime-Event (`start`, `tick`, `keydown`, `message` oder ein eigenes), das ihn ausführt. Sein `run` gibt `false` zurück, um ein Event durchzulassen |

`run` bekommt `self`, `entity(id)`, `parameters`, `values`, `time`, `variables`, seinen eigenen `state`, der zwischen Durchläufen bleibt, `after(seconds, port)`, um später weiterzumachen, `emit(name, value)` und `log(message)`.

Plugins registrieren Nodes stattdessen über ihren Kontext, als `<package>:<type>`, siehe [Plugins](/de/werkzeuge/plugins#graphen-und-nodes).

## Subgraphen

Ein Graph mit **Graph Input**- und **Graph Output**-Nodes ist eine Funktion: Er erscheint als Node in anderen Graphen seiner Art, unter Subgraphs, mit einem Port pro Ein- und Ausgang. Subgraphen enthalten nur Werte, keine Events oder Schritte. Der Editor zeigt sie mit dem Badge *subgraph*.

## Graph-Dateien

Graphen sind JSON-Dateien im Verzeichnis `graphs/` des Projekts, neben `scenes/`: `graphs/<name>.graph.json`, Namen aus Buchstaben, Ziffern, `-` und `_`. Der Editor speichert sie über den Dev-Server, und jedes Release liefert sie mit.

```json
{
  "version": 1,
  "kind": "logic",
  "name": "server-npc",
  "nodes": [
    { "id": "tick", "type": "event.tick", "position": [0, 0] },
    { "id": "move", "type": "entity.addPosition", "position": [240, 0] }
  ],
  "edges": [
    { "from": { "node": "tick", "port": "then" }, "to": { "node": "move", "port": "run" } }
  ],
  "parameters": [
    { "name": "speed", "type": "float", "default": 1.5 }
  ]
}
```

### Graphen aus Plugins

Ein Plugin kann Graphen in einem Verzeichnis `graphs/` seines Pakets mitliefern. Sie heißen `<package>:<name>`, werden unter `/graphs/<package>/<name>.graph.json` ausgeliefert und sind in jedem Release dabei. Der Editor zeigt sie schreibgeschützt; **Copy to project** legt eine bearbeitbare Kopie an.

## Einen Graphen aus Code ausführen

```typescript
import { readGraph } from '@mavonengine/core/Graph/loadGraphFile' // nur Node
import { GraphRuntime } from '@mavonengine/core/Graph/Logic/GraphRuntime'

const runtime = new GraphRuntime(readGraph(root, 'server-npc'), {
  self,                         // eine GraphEntity: Position, Rotation, Scale lesen und setzen
  find: id => entityById(id),
  parameters: { speed: 3 },
  log: message => logger.info(message),
})

runtime.start()               // On Start
runtime.update(delta)         // Delays, dann On Tick
runtime.message('clicked', 'Alice')
```

Ein Graph mit Problemen (unbekannte Nodes, Kanten zwischen unpassenden Ports, ein Node, der in einem Logik-Graphen nicht laufen kann) wirft einen `GraphRuntimeError`, der sie auflistet. Der Editor zeigt dieselbe Liste unter **Problems**.
