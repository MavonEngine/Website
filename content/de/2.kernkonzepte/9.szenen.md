Eine Szene ist eine JSON-Datei unter `scenes/<name>.json` im Projekt-Root (neben `mavonengine.json`). Client und Server laden **dieselbe** Datei, und jede Seite baut nur die Objekte, für die sie eine Factory hat: Der Client baut, was gerendert wird, der Server baut, was er simuliert (Collider, Spiellogik).

Die Map des Multiplayer-Templates liegt in `scenes/main.json`: Himmel, Nebel, Lichter und Boden für den Client, ein Baumfeld für den Server.

## Format der Szenendatei

```json
{
  "version": 1,
  "name": "main",
  "settings": {
    "background": "#87ceeb",
    "fog": { "color": "#87ceeb", "density": 0.012 }
  },
  "objects": [
    {
      "id": "sun",
      "type": "Light:DirectionalLight",
      "name": "Sun",
      "transform": {
        "position": [20, 40, 20],
        "rotation": [0, 0, 0],
        "scale": [1, 1, 1]
      },
      "props": { "color": "#fff4e0", "intensity": 1.2, "castShadow": true }
    }
  ]
}
```

| Feld | Beschreibung |
|-------|-------------|
| `version` | Version des Szenenformats, aktuell `1` |
| `name` | Wird im Editor angezeigt |
| `settings.background` | CSS-Farbe des Hintergrunds (Client) |
| `settings.fog` | `{ color, density }`, angewendet als `FogExp2` (Client) |
| `objects[].id` | Eindeutig innerhalb der Szene; wird auf beiden Seiten als Entity-Schlüssel in der Welt verwendet |
| `objects[].type` | Ein registrierter Szenenobjekt-Typ |
| `objects[].transform` | `position`, `rotation` (Radiant, XYZ) und `scale` als `[x, y, z]` |
| `objects[].props` | Typspezifische Daten |

Szenennamen dürfen Buchstaben, Ziffern, `-` und `_` enthalten.

## Eine Szene laden

### Client

```typescript
const game = new Game(sources, physicsWorld)

// Lädt /scenes/main.json und lädt die Szene, sobald die Ressourcen geladen sind
game.openScene('main')
```

`openScene()` nimmt auch eine URL oder die Szenendaten selbst und gibt ein Promise der geladenen `GameScene` zurück. Das Vite-Plugin liefert `scenes/*.json` im Dev-Modus aus und kopiert sie in den Build.

### Server

```typescript
const server = new Server(logger, physicsWorld, {
  // Der Projekt-Root mit mavonengine.json und scenes/. Standard ist plugins.root
  root: projectRoot,
})

server.start().then(() => {
  server.openScene('main')
})
```

Der Server liest `<root>/scenes/main.json` oder einen Pfad, den du übergibst. Mit `{ watch: true }` — oder standardmäßig, solange der Client über Vite ausgeliefert wird (`client.dev`) — lädt er die Szene neu, sobald sich die Datei ändert, zum Beispiel wenn der Editor sie speichert.

### Auf eine Szene reagieren

Beide Seiten lösen `sceneLoading` und `sceneLoaded` am Spiel aus, auch bei jedem Reload:

```typescript
game.on('sceneLoaded', (scene: GameScene) => {
  // scene.getEntries() listet alle Objekte; entry.object ist gesetzt, wenn diese Seite es gebaut hat
})

game.activeScene // die zuletzt geladene GameScene
```

`loadScene(data, source?)` an `BaseGame` ersetzt die aktive Szene direkt durch Szenendaten, die du bereits hast.

## Szenenobjekt-Typen

Ein Typ legt fest, wie ein Objekt auf jeder Seite gebaut und wie es gespeichert wird. Registriere ihn mit `registerSceneObject()`:

```typescript
import { registerSceneObject } from '@mavonengine/core/Scene/SceneObjectRegistry'

// Server: nur Collider und Logik bauen
registerSceneObject<TreeField>({
  type: 'TreeField',
  label: 'Tree field',
  server: data => new TreeField(data),
})
```

```typescript
// Client: bauen, was gerendert wird, und festlegen, was gespeichert wird
registerSceneObject<Crate>({
  type: 'Crate',
  client: data => new Crate(new Vector3(...data.transform.position), data.props),
  serialize: crate => ({ color: crate.color }),
})
```

| Feld | Beschreibung |
|-------|-------------|
| `type` | Schlüssel, der in der Szenendatei verwendet wird |
| `label` | Wird im Editor angezeigt, Standard ist `type` |
| `client(data, ctx)` | Baut das Objekt auf dem Client. Gib ein `GameObject` zurück, oder nichts, um es zu überspringen |
| `server(data, ctx)` | Baut das Objekt auf dem Server |
| `serialize(object)` | Die zu speichernden Props. Die Transformation wird automatisch gespeichert. Ohne diese Funktion bleiben die Props so, wie sie geladen wurden |
| `transformTarget(object)` | Das `Object3D`, das der Editor bewegt. Standard ist `object.instance` |

Registrierst du denselben Typ auf beiden Seiten, werden die Definitionen zusammengeführt. Eine Seite ohne Factory überspringt das Objekt, behält aber seine Daten, sodass beim Speichern nie etwas verloren geht. Plugins registrieren Typen mit `ctx.registerSceneObject()`, mit dem Schlüssel `<package>:<type>`.

Szenenobjekte sind Map-Daten, die jeder Client selbst lädt, daher sendet der Server sie **nicht** im Zustandsabgleich — außer sie sind vernetzte Entities (`NetworkedGameObject`).

### Eingebaute Typen (Client)

| Typ | Props |
|------|-------|
| `Primitive:<Name>` | Box, Capsule, Circle, Cone, Cylinder, Dodecahedron, Edges, Extrude, Icosahedron, Lathe, Octahedron, Plane, Polyhedron, Ring, Shape, Sphere, Tetrahedron, Torus, TorusKnot, Tube, Wireframe. Material- und Schatten-Props; `width` / `height` für Plane |
| `Light:<Name>` | Three.js-Lichter, z.B. `Light:AmbientLight`, `Light:DirectionalLight`. `color`, `intensity`, `castShadow`, … |
| `Model` | `resource` (Name eines geladenen `gltfModel`), `castShadow`, `receiveShadow` |
| `prefab:<key>` | Jedes Prefab aus der [Prefab-Registry](/de/prefabs) |

## Szenen bearbeiten

Der [Level-Editor](/de/kernkonzepte/level-editor) zeigt die aktive Szene in seinem **Scene**-Panel, markiert ungespeicherte Änderungen und speichert mit `Ctrl+S` (oder `Cmd+S`) über den Dev-Server zurück nach `scenes/<name>.json`. Der Spielserver lädt die Datei dann neu, und jeder Client bekommt die neue Map.

`GameScene` lässt sich auch aus dem Code ändern: `create(type, data)`, `remove(id)`, `setProps(id, props)`, `setName(id, name)`, `setSettings(settings)` und `serialize()`, um das JSON zurückzubekommen. Es löst `objectAdded`, `objectRemoved`, `settingsChanged` und `changed` aus.
