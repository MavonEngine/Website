`InputManager` verfolgt den Status von Tastatur, Maus, Gamepads und VR-Controllern und bietet Raycasting-Utilities zur Umrechnung von Bildschirmkoordinaten in Weltpositionen.

```typescript
// Zugriff über game.input
const input = game.input
```

### Fokus

Ein Klick auf das Canvas nimmt dem Element, das den Fokus hatte, etwa einem Chat-Eingabefeld, den Fokus und gibt ihn dem Fenster des Spiels, sodass Tastatureingaben zum Spiel zurückkehren, auch in einem eingebetteten iframe. Verliert das Fenster den Fokus (Klick aus einem iframe heraus, Alt-Tab) oder wird der Tab ausgeblendet, werden alle gehaltenen Tasten und Maustasten losgelassen, da ihr `keyup` und `mouseup` nie ankommen.

## Tastatur

Tasten werden durch ihren [KeyboardEvent.code](https://developer.mozilla.org/en-US/docs/Web/API/KeyboardEvent/code)-Wert verfolgt.

```typescript
// Prüfen ob eine Taste aktuell gedrückt ist
if (input.keysPressed.has('KeyW')) {
  // W ist gedrückt
}

if (input.keysPressed.has('Space')) {
  // Leertaste ist gedrückt
}
```

### Tastatur-Events

```typescript
input.on('keydown', (event: KeyboardEvent) => {
  console.log('gedrückt:', event.code)
})

input.on('keyup', (event: KeyboardEvent) => {
  console.log('losgelassen:', event.code)
})
```

## Maus

Der Status der Maustasten wird nach Tastenindex verfolgt (0 = links, 1 = Rad, 2 = rechts).

```typescript
if (input.mousePressed.has(0)) {
  // Linke Maustaste ist gedrückt
}
```

### Cursorposition

Die normalisierte Cursorposition im Bereich `[-1, 1]` auf beiden Achsen, relativ zum Canvas des Spiels statt zum Fenster (im Editor ist das Canvas ein Panel):

```typescript
input.cursor // THREE.Vector2, bei jedem mousemove und pointerdown aktualisiert
```

## Weltposition-Raycasting

Wandle die Cursorposition mit `getPointerWorldPosition` in eine Weltkoordinate um:

```typescript
const worldPos = input.getPointerWorldPosition()
// Gibt THREE.Vector3 | null zurück
```

**Parameter:**

| Parameter | Typ | Beschreibung |
|-----------|------|-------------|
| `except` | `Object3D[]` | Objekte, die vom Raycasting ausgeschlossen werden |
| `only` | `Object3D[]` | Nur gegen diese Objekte raycasten |

```typescript
// Nur gegen das Terrain raycasten
const pos = input.getPointerWorldPosition(undefined, [terrain.instance])
```

## Gamepads

Xbox-, PlayStation-, Nintendo- und generische Controller stehen über `input.gamepads` zur Verfügung, einen `GamepadManager`. Er wird einmal pro Spiel-Update abgefragt, bevor die Welt aktualisiert wird.

> Browser geben einen Controller erst frei, nachdem eine Taste darauf gedrückt wurde, während die Seite den Fokus hat.

```typescript
import { GamepadButton } from '@mavonengine/core/GamepadManager'

const pad = input.gamepads.primary // erster verbundener Controller, oder undefined

if (pad) {
  // Sticks nach der Deadzone, Y ist positiv, wenn nach oben gedrückt
  move.set(pad.leftStick.x, 0, -pad.leftStick.y)

  if (pad.justPressed(GamepadButton.South)) // A bei Xbox, Kreuz bei PlayStation
    jump()

  const throttle = pad.value(GamepadButton.RightTrigger) // 0 - 1
}

// Beliebiger verbundener Controller
input.gamepads.isPressed(GamepadButton.Start)
input.gamepads.justPressed(GamepadButton.A)
```

### Tasten

`GamepadButton` folgt dem W3C-Standard-Mapping. Verwende die layoutunabhängigen Namen (`South`, `East`, `West`, `North`, `LeftBumper`, `RightTrigger`, `DPadUp`, …) oder die Aliase für Xbox (`A`, `B`, `LB`, `RT`, `View`, `Menu`) und PlayStation (`Cross`, `Circle`, `L1`, `R2`, `Share`, `Options`).

### GamepadState

| Mitglied | Beschreibung |
|--------|-------------|
| `type` | `'xbox'`, `'playstation'`, `'nintendo'` oder `'generic'`, anhand der ID erkannt |
| `leftStick` / `rightStick` | `Vector2` nach der radialen Deadzone |
| `axes` | Rohe Achsen, wie vom Browser gemeldet |
| `isPressed(button)` | Taste wird gehalten |
| `justPressed(button)` / `justReleased(button)` | Taste hat sich seit dem vorherigen Update geändert |
| `value(button)` | Analogwert, 0 - 1 (Trigger) |
| `buttonLabel(button)` | Beschriftung für die Controller-Familie, z.B. `"Cross"` oder `"A"` |

### Einstellungen

```typescript
input.gamepads.stickDeadzone = 0.15   // Stick-Eingaben darunter werden ignoriert
input.gamepads.buttonThreshold = 0.5  // analoge Tasten gelten darüber als gedrückt
```

### Events

```typescript
input.gamepads.on('connected', (pad) => console.log(`${pad.type} connected`))
input.gamepads.on('disconnected', (pad) => {})
input.gamepads.on('buttondown', ({ gamepad, button }) => console.log(gamepad.buttonLabel(button)))
input.gamepads.on('buttonup', ({ gamepad, button }) => {})
```

### Vibration

```typescript
await input.gamepads.vibrate(pad.index, { duration: 200, strongMagnitude: 1, weakMagnitude: 0.5 })
// Löst zu false auf, wenn der Controller oder Browser es nicht unterstützt
```

Die Statusleiste des [Level-Editors](/de/kernkonzepte/level-editor) zeigt verbundene Controller mit einer Live-Debug-Ansicht.

## VR-Controller

Sobald [`game.enableXR()`](/de/kernkonzepte/vr) aufgerufen wurde, liest `input.xr` die Controller des Headsets nach Hand, egal welchen Slot die Session ihnen gibt. Es wird mit den anderen Eingaben bei jedem Spiel-Update abgefragt und hat dieselbe API wie die Gamepads:

```typescript
import { XRControllerButton } from '@mavonengine/core/XRInput'

const xr = game.input.xr!

// Thumbstick nach der Deadzone, Y ist positiv, wenn nach vorne gedrückt
const stick = xr.left.stick

if (xr.right.justPressed(XRControllerButton.A))
  jump()

const grip = xr.left.value(XRControllerButton.Squeeze) // 0 - 1

// Einer der beiden Controller
xr.isPressed(XRControllerButton.Trigger)
```

`XRControllerButton` folgt dem WebXR-[xr-standard-Mapping](https://www.w3.org/TR/webxr-gamepads-module-1/#xr-standard-gamepad-mapping), das Controller von Quest, Index, Vive, Pico und Windows Mixed Reality verwenden: `Trigger`, `Squeeze`, `Touchpad`, `Thumbstick`, `Primary` / `Secondary` und die Aliase `A`, `B` (rechts) und `X`, `Y` (links).

| `XRController` (`xr.left`, `xr.right`) | |
| --- | --- |
| `hand` / `connected` | `'left'` oder `'right'`, und ob ein Controller (oder eine getrackte Hand) da ist |
| `stick` / `axes` | Der Thumbstick nach der Deadzone und die rohen Achsen |
| `isPressed()` / `justPressed()` / `justReleased()` / `value()` | Wie bei einem Gamepad |
| `ray` / `grip` | Folgen, wohin der Controller zeigt (-Z nach vorne) und wo er gehalten wird, um Modelle oder gehaltene Gegenstände anzuhängen. Beide liegen im Kamera-Rig und bewegen sich also mit dem Spieler |
| `setRaycaster(raycaster)` / `getWorldPosition()` | Einen Raycaster entlang des Controllers ausrichten, und von wo er zeigt |
| `vibrate(intensity, duration)` | Haptik; ergibt false, wenn der Controller es nicht kann |

`xr.raycast(hand, raycaster, objects)` gibt, worauf ein Controller zeigt, das Nächste zuerst. `xr.stickDeadzone` und `xr.buttonThreshold` funktionieren wie bei den Gamepads.

```typescript
xr.on('connected', controller => console.log(`${controller.hand} controller`))
xr.on('buttondown', ({ controller, button }) => {})
// Die Hauptaktion der Session: ein Trigger-Zug, oder ein Pinch beim Hand-Tracking
xr.on('select', ({ controller }) => shoot(controller))
xr.on('squeezestart', ({ controller }) => grab(controller))
```

Events: `connected` / `disconnected`, `buttondown` / `buttonup`, `selectstart` / `selectend` / `select` und `squeezestart` / `squeezeend` / `squeeze`.

`enableXR({ input })` legt fest, wie die Controller erscheinen:

| Option | Standard | |
| --- | --- | --- |
| `controllerModels` | `true` | Ihre 3D-Modelle zeigen, aus den WebXR-Input-Profilen |
| `controllerModelsPath` | das jsdelivr-CDN | Woher die Modelle laden, um sie selbst zu hosten |
| `rays` / `rayLength` | `true` / `5` | Eine Zeigelinie aus jedem Controller, und wie weit sie in Metern reicht |

`input: false` lässt die Controller weg.
