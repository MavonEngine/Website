Jeder Spielserver hat eine Job-Warteschlange, `server.queue` im Code des Spiels und `ctx.queue` in einem Plugin. Leg langsame oder unzuverlässige Arbeit darauf, etwa Aufrufe anderer Dienste oder das Senden von Mails, damit kein Tick darauf wartet. Ein Job, der wirft, wird erneut versucht und unter den fehlgeschlagenen Jobs aufbewahrt, sobald er keine Versuche mehr hat.

Die Warteschlange gehört zu `@mavonengine/core`, es gibt also nichts zu installieren. Ihre Jobs liegen im Speicher, oder in der Datenbank, wenn das Projekt ein [Datenbank-Plugin](/de/werkzeuge/datenbank) wie `@mavonengine/sqlite` hat. Dort überstehen sie einen Neustart.

## Einen Job schreiben

Ein Job ist eine Klasse, die `Job` erweitert und `handle()` implementiert:

```typescript
import Job from '@mavonengine/core/Queue/Job'

export class GrantReward extends Job<{ player: string, coins: number }> {
  static jobName = 'grant-reward'
  tries = 3
  backoffMs = [1000, 5000]

  async handle() {
    await addCoins(this.data.player, this.data.coins)
  }

  failed(error: Error) {
    // Einmal aufgerufen, wenn der letzte Versuch geworfen hat
  }
}
```

| Feld | Standard | |
| --- | --- | --- |
| `static jobName` | der Klassenname | Der Name, unter dem der Job gespeichert und nachgeschlagen wird. Setz ihn, damit eine umbenannte Klasse, oder eine, die ein Bundler umbenennt, wartende Jobs nicht ohne Klasse zurücklässt. In einem Plugin gehört der Name des Plugins hinein, etwa `chat:expire-mute` |
| `queue` | `default` | Die Warteschlange, auf die er kommt |
| `tries` | `1` | Wie oft er versucht wird, bevor er als fehlgeschlagen gilt |
| `backoffMs` | `0` | Wie lange vor einem erneuten Versuch gewartet wird, in ms: eine Zahl für jeden Versuch, oder eine pro Versuch, wobei sich die letzte wiederholt, etwa `[1000, 10_000, 60_000]` |

`data` wird als JSON gespeichert, und der Job wird daraus mit `new GrantReward(data)` neu gebaut, wenn er läuft, auch nach einem Neustart. Beschränke es auf das, was JSON hält: IDs, keine Entities oder Verbindungen.

`handle()` bekommt den Kontext des Laufs: `id` (über die Wiederholungen hinweg dieselbe), `queue` und `attempt`, `1` beim ersten Versuch. Ein Wurf oder eine Ablehnung ist ein fehlgeschlagener Versuch.

## Jobs einreihen

```typescript
const id = await server.queue.dispatch(new GrantReward({ player: account.id, coins: 10 }))

server.queue.dispatch(new GrantReward(data), { delayMs: 60_000 }) // in einer Minute
server.queue.dispatch(new GrantReward(data), { queue: 'rewards' })

await server.queue.dispatchSync(new GrantReward(data)) // jetzt, in diesem Aufruf
```

- `dispatch()` erfüllt sich mit der ID des Jobs, sobald er gespeichert ist, nicht wenn er gelaufen ist.
- Jobs können vor `start()` eingereiht werden. Sie laufen, sobald es fertig ist.
- `dispatchSync()` führt den Job im Aufruf aus, ohne Warteschlange: keine Wiederholungen, und ein Wurf wird weitergegeben.

### In einem Plugin

Registriere die Job-Klassen des Plugins in `setup()`. Ein Job, den der Prozess einreiht, registriert seine Klasse selbst, aber ein vor einem Neustart eingereihter Job läuft erst, wenn seine Klasse registriert ist:

```typescript
export default defineServerPlugin({
  setup(ctx) {
    ctx.queue.register(ExpireMute)
  },
  http(app, ctx) {
    app.post('/api/my-plugin/mute', ctx.requireAdmin, async (req, res) => {
      await ctx.queue.dispatch(new ExpireMute({ id: req.body.id }), { delayMs: req.body.minutes * 60_000 })
      res.status(202).end()
    })
  },
})
```

Jobs, deren Klasse nicht registriert ist, warten in der Warteschlange. Zwei verschiedene Klassen mit demselben `jobName` werfen.

## Fehlgeschlagene Jobs

```typescript
const failed = await server.queue.failed(50) // die neuesten zuerst
await server.queue.retry(failed[0].id) // zurück auf seine Warteschlange, mit neuen Versuchen
await server.queue.forget(failed[0].id)
```

Ein fehlgeschlagener Job hat seine `id`, `queue`, `name`, `payload`, `attempts`, `failedAt` und den `error` seines letzten Versuchs, mit Stack. `await server.queue.size('default')` zählt die Jobs einer Warteschlange, die noch nicht fertig sind, verzögerte und laufende eingeschlossen; ohne Namen über alle Warteschlangen.

## Optionen

Gesetzt als `queue` in den [Optionen des Servers](/de/netzwerk/server#optionen):

```typescript
const server = new MyServer(logger, physicsWorld, {
  plugins: { root: projectRoot },
  queue: { concurrency: 4, queues: ['high', 'default'] },
})
```

| Option | Standard | |
| --- | --- | --- |
| `driver` | `database` mit Datenbank-Plugin, sonst `memory` | Wo Jobs liegen. `database` verwendet die Tabellen `core_jobs` und `core_failed_jobs` |
| `work` | `true` | Jobs in diesem Prozess ausführen. Schalte es auf einem Server ab, der nur einreiht |
| `concurrency` | `1` | Wie viele Jobs gleichzeitig laufen |
| `queues` | jede Warteschlange | Die abzuarbeitenden Warteschlangen, die erste zuerst: Mit `['high', 'default']` läuft ein Job auf `default` nur, solange `high` keinen fälligen hat. Ohne sie läuft der am längsten fällige Job zuerst |
| `pollIntervalMs` | `1000` | Wie oft ein untätiger Worker nach fälligen Jobs sieht |
| `retryAfterMs` | `90000` | Ein Job, der nach dieser Zeit noch läuft, gilt als verlassen, etwa weil sein Server beendet wurde, und läuft erneut. Halte den Wert über der längsten Laufzeit eines Jobs |

- **Mit Datenbank:** Die Migration der Warteschlange läuft beim Start des Servers, ohne den Start aufzuhalten; zwischenzeitlich eingereihte Jobs ziehen mit um. Schlägt die Migration fehl, bleibt die Warteschlange im Speicher, und das Log sagt es.
- **Im Speicher:** Jobs gehen verloren, wenn der Server stoppt.
- **Beenden:** `server.stop()` nimmt keine Jobs mehr an und wartet auf die laufenden, bevor es die Datenbank schließt, siehe [Beenden](/de/netzwerk/server#beenden).

## Beobachten

Der Overview-Tab des [Dashboards](/de/werkzeuge/monitoring#queue) zeigt die Warteschlange als Graph: eingereihte, verarbeitete und fehlgeschlagene Jobs und wie viele laufen. Die Metriken enthalten sie als `queue`, mit dem Treiber, ob dieser Server die Warteschlange abarbeitet, und einem Verlauf von Messwerten.
