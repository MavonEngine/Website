`@mavonengine/chat` ist ein Engine-[Plugin](/de/werkzeuge/plugins), das einem Multiplayer-Spiel Text-Chat hinzufügt. Es setzt eine Chatbox in die linke untere Ecke des Spiels, reicht das, was Spieler tippen, über die eigene Verbindung des Spiels weiter und gibt dem Server die üblichen Schutzmechanismen: ein Längenlimit, ein Rate-Limit, Stummschaltungen und eine Admin-API.

```bash
npx @mavonengine/cli install @mavonengine/chat
```

Starte den Spielserver neu und drück im Spiel `Enter`, um zu tippen.

## Was es tut

- **Chatbox**: ein Nachrichtenverlauf und ein Eingabefeld, mit reinem DOM gebaut, sodass sie unabhängig von deinem UI-Framework funktioniert. `Enter` beginnt das Tippen und sendet, `Escape` verlässt es. Während du tippst, erreichen die Tasten das Spiel nicht.
- **Serverseitige Prüfungen**: Was ein Spieler sendet, wird bereinigt (Steuerzeichen und Zeilenumbrüche werden zu Leerzeichen), in der Länge und in der Rate begrenzt. Wird eine Nachricht nicht weitergegeben, bekommt der Absender einen Hinweis mit dem Grund.
- **Umgebungs-Chat**: Mit einer `range` hören nur Spieler eine Nachricht, die dem Absender so nah sind.
- **Beitritts- und Austrittshinweise**: „Ada joined“, „Ada left“, mit dem Namen, den das Spiel dem Spieler gegeben hat.
- **Verlauf**: Ein Client, der sich verbindet, bekommt die letzten Nachrichten gesendet.
- **Stummschaltungen und Ankündigungen**: über die [Admin-API](#admin-api).
- **Hooks für dein Spiel**: Callbacks, die Nachrichten auf dem Server ändern, verwerfen, beantworten oder umleiten, und Listener für Nachrichten, Hinweise und den Verlauf im Browser. Siehe [In deinem Spiel](#in-deinem-spiel).
- **Anpassbares Aussehen**: eine Ecke, in der sie sitzt, Farben als CSS Custom Properties und einfache Klassennamen für den Rest. Siehe [Styling](#styling).

Nachrichten werden immer als Text angezeigt, nie als HTML, auf dem Server und im Browser.

## Optionen

Setz sie unter dem Plugin in `mavonengine.json`. Alle sind optional.

```json
{
  "plugins": {
    "@mavonengine/chat": {
      "options": {
        "maxLength": 200,
        "rateLimit": { "messages": 5, "perSeconds": 10 },
        "history": 50,
        "range": 0,
        "announce": true
      }
    }
  }
}
```

| Option | Standard | |
|---|---|---|
| `maxLength` | `200` | Längste Nachricht, in Zeichen. Auch das Limit des Eingabefelds |
| `rateLimit` | `5` pro `10` s | Wie viele Nachrichten ein Spieler innerhalb von wie vielen Sekunden senden darf |
| `history` | `50` | Letzte Nachrichten, die ein Client beim Verbinden bekommt. `0` für keine |
| `range` | `0` | Wie weit eine Nachricht zu hören ist, in Welteinheiten. `0` heißt, alle hören sie. Mit einer Reichweite wird kein Verlauf gesendet, da er außer Hörweite gesagt worden sein könnte |
| `announce` | `true` | Im Chat ansagen, wenn ein Spieler beitritt oder geht |
| `path` | `/api/chat` | URL-Pfad der Admin-API |
| `openKey` | `Enter` | Taste, die das Tippen beginnt |
| `placeholder` | `Press Enter to chat` | Wird im leeren Eingabefeld angezeigt |
| `position` | `bottom-left` | Ecke, in der die Chatbox sitzt: `bottom-left`, `bottom-right`, `top-left` oder `top-right` |
| `maxMessages` | `100` | Zeilen, die die Chatbox behält |
| `ui` | `true` | `false` lässt die Chatbox weg, für ein Spiel, das den Chat selbst anzeigt, siehe [Im Browser](#im-browser) |

## Namen

Ein Spieler wird mit seinem `displayName` angesprochen, wenn das Spiel einen mit `setDisplayName()` gesetzt hat, sonst mit seinem `name`-Feld, sonst mit seiner ID. Der Beitrittshinweis wartet bis zu zwei Sekunden darauf, dass das Spiel einem neuen Spieler einen Namen gibt.

## In deinem Spiel

Das Spiel hört über `chat()` im Chat mit und redet darin mit, auf dem Server und im Browser. Jede Funktion, die einen Callback registriert, gibt eine Funktion zurück, die ihn wieder entfernt.

### Auf dem Server

```typescript
import { chat } from '@mavonengine/chat/server'

const hooks = chat(server)
```

Ruf es jederzeit auf, auch vor `server.start()`: Was du registrierst, gilt, sobald das Plugin läuft.

**`hooks.intercept(callback)`** redet bei jeder Nachricht mit, die ein Spieler sendet, bevor sie rausgeht. Es läuft nach den eigenen Prüfungen des Chats (Stummschaltung, Länge, Rate-Limit) und bekommt den bereinigten Text und den Absender. Was es zurückgibt, entscheidet, was passiert:

| Rückgabe | Die Nachricht |
|---|---|
| nichts | geht unverändert raus |
| `false` | wird verworfen, und niemand erfährt davon |
| ein String | geht stattdessen mit diesem Text raus |
| `{ text?, to? }` | geht mit diesem Text raus, und mit `to` nur an diese Spieler-IDs und ihren Absender. Sie wird dann nicht in den Verlauf aufgenommen |

```typescript
// Ein Wortfilter
hooks.intercept(message => message.text.replace(/\bdarn\b/gi, '****'))

// Ein Befehl: nur dem Absender antworten und nichts senden
hooks.intercept((message, tools) => {
  if (message.text !== '/roll')
    return
  tools.reply(`You rolled ${1 + Math.floor(Math.random() * 6)}`)
  return false
})

// Flüstern: /w <Spieler-ID> <Text>
hooks.intercept((message) => {
  const whisper = /^\/w (\S+) (.+)$/.exec(message.text)
  if (whisper)
    return { text: whisper[2], to: [whisper[1]] }
})
```

`tools.reply(text)` sagt dem Absender etwas, das sonst niemand sieht, und `tools.player` ist die Entity des Absenders. Interceptors laufen in der Reihenfolge, in der sie hinzugefügt wurden. Einer, der eine Exception wirft, verwirft die Nachricht und loggt den Fehler, damit ein Bug in einem Filter nicht durchlässt, was er aufhalten sollte.

**`hooks.onMessage(callback)`** erfährt von jeder Nachricht, nachdem sie rausgegangen ist, auch von denen des Servers selbst (`message.from` ist `null`), mit den IDs der Spieler, die sie bekommen haben:

```typescript
hooks.onMessage((message, { recipients }) => {
  database.saveChat(message.from?.id ?? null, message.text, recipients)
})
```

**`hooks.announce(text)`**, **`hooks.mute(playerId, minutes?)`** und **`hooks.unmute(playerId)`** tun, was die Admin-API tut, und **`hooks.room`** ist der Chat selbst, mit Verlauf, Stummschaltungen und Optionen.

### Im Browser

```typescript
import { chat } from '@mavonengine/chat/client'

const talk = chat(game)

// Jede Nachricht, sobald sie gesagt wird, z.B. für eine Sprechblase über dem Spieler
talk.onMessage((message) => {
  if (message.from)
    world.entities.items.get(message.from.id)?.showChatBubble(message.text)
})

// Was der Server nur diesem Spieler sagt, etwa „you are sending messages too fast“
talk.onNotice(text => hud.toast(text))

// Die letzten Nachrichten, gesendet, wenn das Spiel sich verbindet
talk.onHistory(messages => myChat.fill(messages))

// Etwas als Spieler sagen. False, solange das Spiel nicht verbunden ist
talk.send('gg')
```

Dieselben drei kommen als Events auf dem Spiel an, für Code, der lieber dort lauscht: `chat:message`, `chat:notice` und `chat:history`.

**Die Chatbox** ist `talk.box`: Füge eigene Zeilen mit `box.add(message)` und `box.notice(text)` hinzu oder nimm sie mit `box.hide()` und `box.show()` vom Bildschirm.

**Dein eigenes Chat-UI**: Setz `"ui": false` in den Optionen des Plugins und bau es auf `onMessage`, `onNotice`, `onHistory` und `send` auf. Du bekommst alles, was die eingebaute Box bekommt.

## Styling

- **Wo sie sitzt**: `"position"` in den Optionen, eines von `bottom-left` (Standard), `bottom-right`, `top-left` und `top-right`.
- **Farben**: CSS Custom Properties auf `.mavonengine-chat`. Setz sie in deinem eigenen Stylesheet:

```css
.mavonengine-chat {
  --chat-bg: rgb(20 10 30 / 80%);
  --chat-bg-idle: rgb(20 10 30 / 40%);
  --chat-text: #fff;
  --chat-muted: #b8a9c9;
  --chat-accent: #c77dff;
  --chat-border: rgb(255 255 255 / 20%);
}
```

- **Alles andere**: Die Box ist reines DOM mit globalen Klassennamen, dein CSS kann also jeden Teil umgestalten: `.mavonengine-chat` (die Box), `.mavonengine-chat-log`, `.mavonengine-chat-input`, `.mavonengine-chat-name`, `.mavonengine-chat-system` (was der Server sagt) und `.mavonengine-chat-notice`. Die Box hat die Klasse `open`, während darin getippt wird.

## Admin-API

| | |
|---|---|
| `GET /api/chat/messages` | Die letzten Nachrichten |
| `POST /api/chat/messages` | Etwas ankündigen: `{ "text": "Server restarts in 5 minutes" }` |
| `GET /api/chat/mutes` | Die stummgeschalteten Spieler |
| `POST /api/chat/mutes` | Einen Spieler stummschalten: `{ "playerId": "…", "minutes": 10 }`. Ohne `minutes`, bis es aufgehoben wird |
| `DELETE /api/chat/mutes/:playerId` | Die Stummschaltung eines Spielers aufheben |

Die API ist durch das [Admin-Token](/de/netzwerk/server#admin-token) des Spielservers geschützt, dasselbe wie bei jeder anderen Admin-Route des Servers: Setz `MAVONENGINE_ADMIN_TOKEN` (oder `adminToken` in den Optionen des Servers) und sende es als `Authorization: Bearer <token>`. Ohne Token antwortet die API nur auf Anfragen von localhost. Der Chat hat kein eigenes Token.

```bash
curl -X POST localhost:8050/api/chat/mutes -d '{ "playerId": "abc123", "minutes": 10 }'
curl -X POST https://game.example.com/api/chat/mutes -H "Authorization: Bearer $MAVONENGINE_ADMIN_TOKEN" -d '{ "playerId": "abc123" }'
```

Spieler-IDs sind die, die das [Dashboard](/de/werkzeuge/monitoring) in seinem Players-Tab auflistet.

## Grenzen

- Ein Spieler wird über die ID seiner Verbindung erkannt. Ein stummgeschalteter Spieler, der sich neu verbindet, hat eine neue ID und ist nicht mehr stummgeschaltet. Dauerhafte Stummschaltungen brauchen Accounts, die die Engine noch nicht hat.
- Es gibt eine einzige Unterhaltung, ohne eingebaute Kanäle oder private Nachrichten. Ein Spiel kann sie mit `intercept` ergänzen, das eine Nachricht nur an einige Spieler senden kann, aber die Chatbox hat keine Tabs, um sie getrennt anzuzeigen.
- Interceptors sind synchron: Eine Prüfung, die auf etwas warten muss, etwa einen Moderationsdienst, wird nicht unterstützt.
- Nichts wird gespeichert. Verlauf und Stummschaltungen sind weg, wenn der Server neu startet. `onMessage` auf dem Server ist die Stelle, um Nachrichten selbst zu speichern.
