Ein Engine-Plugin ist ein npm-Paket, das dem Client, dem Spielserver oder beiden Code hinzufügt und Prefabs und Assets mitbringen kann. Installiere eines mit der [CLI](/de/werkzeuge/cli):

```bash
npx @mavonengine/cli install my-custom-plugin
```

## Offizielle Plugins

Die offiziellen Plugins stehen in [`plugins.json`](https://github.com/MavonEngine/Core/blob/main/plugins.json) im Root des MavonEngine-Repositorys:

| Plugin | Läuft auf | |
| --- | --- | --- |
| [`@mavonengine/http-monitoring`](/de/werkzeuge/monitoring#browser-dashboard) | Server | Das Spielserver-Dashboard im Browser |
| [`@mavonengine/chat`](/de/werkzeuge/chat) | Client und Server | Text-Chat im Spiel mit Rate-Limit, Stummschaltungen, Umgebungs-Chat und einer Admin-API |

`mavonengine plugins` gibt die Liste aus und liest sie jedes Mal von GitHub, ein neues Plugin erscheint also, sobald es hinzugefügt wurde. Dieselbe Liste, mit dem, was dein Projekt noch nicht hat, erscheint in:

- dem **Plugins**-Tab des [Dashboards](/de/werkzeuge/monitoring#terminal-dashboard), wo `i` unter `mavonengine dev` das ausgewählte Plugin installiert;
- der **Plugins**-Ansicht des [Editors](/de/kernkonzepte/level-editor#server-und-plugins), die auch die Readme jedes Plugins zeigt und beliebige andere Pakete installiert;
- dem Tool `available_plugins` des [MCP-Servers](/de/werkzeuge/ki-assistenten#plugin-tools), damit ein Assistent ein Plugin vorschlagen kann, statt nachzubauen, was eines bereits kann.

Die Installation aus dem Dashboard oder dem Editor fragt vorher nach, da der Code eines Pakets auf deinem Rechner läuft, fügt das Plugin dann zu `mavonengine.json` hinzu und startet die Dev-Server neu.

Um ein eigenes Plugin aufzulisten, füge einen Eintrag zu `plugins.json` hinzu: `package` (der npm-Name) ist erforderlich; `name`, `description`, `target`, `engine` (der unterstützte `@mavonengine/core`-Bereich), `homepage` und `readme` (die URL seiner README als Markdown) sind optional.

## mavonengine.json

Aktivierte Plugins stehen in `mavonengine.json` im Projekt-Root, neben `package.json`:

```json
{
  "plugins": {
    "my-custom-plugin": { "enabled": true, "prefabs": ["Tree"], "options": { "density": 2 } }
  }
}
```

| Feld | Beschreibung |
|-------|-------------|
| `enabled` | `false` schaltet das Plugin ab, ohne es zu deinstallieren |
| `prefabs` | Die Plugin-Prefabs, die das Projekt verwendet. Der Editor fügt ein Prefab hinzu, wenn du es platzierst. Nur die Assets dieser Prefabs (plus die geteilten) kommen ins Release |
| `options` | Wird dem Plugin als `ctx.options` übergeben |

Der Client lädt neu, wenn sich die Plugins ändern. Starte den Spielserver neu, um ein neues Server-Plugin zu laden.

## Ein Projekt einrichten

Projekte, die mit `mavonengine create` erstellt wurden, sind bereits eingerichtet. Für ein bestehendes Projekt:

```typescript
// Client: vor new Game()
import Game from '@mavonengine/core/Game'
import plugins from 'virtual:mavonengine/plugins'

Game.usePlugins(plugins)
```

```typescript
// Server: das Verzeichnis mit mavonengine.json
const server = new MyServer(logger, physicsWorld, { plugins: { root: projectRoot } })
await server.start()
```

Die Vite-Konfiguration des Clients muss `@mavonengine/core/vite.config` erweitern. Diese stellt `virtual:mavonengine/plugins` bereit, liefert Plugin-Assets im Dev-Modus aus und kopiert sie ins Release.

## Ein Plugin schreiben

Füge der `package.json` des Plugins ein `mavonengine`-Feld hinzu:

```json
{
  "name": "my-custom-plugin",
  "type": "module",
  "mavonengine": {
    "target": "both",
    "client": "./dist/client.js",
    "server": "./dist/server.js",
    "engine": "^0.0.22",
    "assets": {
      "dir": "./assets",
      "shared": ["textures/bark.png"],
      "prefabs": {
        "Tree": ["models/tree.glb"],
        "Rock": ["models/rock.glb"]
      }
    }
  }
}
```

- `target`: `client`, `server` oder `both`. Die passenden Einträge sind erforderlich.
- `assets`: Pfade relativ zu `dir` (Standard `assets`), ausgeliefert unter `/plugins/<package>/<path>`. Im Dev-Modus alle; in einem Release nur die geteilten und die der verwendeten Prefabs.

Jeder Einstiegspunkt exportiert das Plugin als Default-Export. Jeder Hook bekommt als letztes Argument den Kontext des Plugins, mit `package`, `options`, `game` und `logger`.

### Client

```typescript
import { defineClientPlugin } from '@mavonengine/core/Plugins/types'

export default defineClientPlugin({
  assets: ctx => [{ name: 'tree', type: 'gltfModel', path: ctx.assetUrl('models/tree.glb') }],
  setup(ctx) {
    ctx.registerPrefab({
      name: 'Tree',
      spawn: position => ({ object: new Tree(position) }),
    })
  },
  update(delta, ctx) {},
  // Nur im Dev-Modus, wenn der Editor startet
  editor(ctx) {
    ctx.editor.on('objectSelected', () => {})
  },
})
```

Der Client-Kontext hat außerdem `registerSceneObject()`, um [Szenenobjekt-Typen](/de/kernkonzepte/szenen#szenenobjekt-typen) hinzuzufügen.

### Server

```typescript
import { defineServerPlugin } from '@mavonengine/core/Plugins/types'

export default defineServerPlugin({
  setup(ctx) {},
  // Läuft nach den eigenen onHttp-Routen des Servers, vor dem Spiel-Client
  http(app, ctx) {
    app.get('/api/my-plugin/status', (_req, res) => res.json({ ok: true }))
  },
  onConnection(channel, client, ctx) {},
  onDisconnect(channel, ctx) {},
  tick(delta, ctx) {},
  destroy(ctx) {},
})
```

Der Server-Kontext hat außerdem `server`, `projectRoot`, `registerSceneObject()`, `requireAdmin` und `adminToken`. Plugins erreichen die Physikwelt über `ctx.game.physicsWorld`, siehe [Physik](/de/kernkonzepte/physik).

Die Routen, die ein Plugin registriert, werden mit seinem Namen in den Tabs Routes und Plugins des Dashboards aufgeführt. Beschreibe mit [`describeRoute()`](/de/netzwerk/server#routen-beschreiben), was sie tun.

### Admin-Routen

Schütze die Admin-Routen eines Plugins mit `ctx.requireAdmin`, das das [Admin-Token](/de/netzwerk/server#admin-token) des Servers verlangt, statt dem Plugin ein eigenes Token zu geben:

```typescript
export default defineServerPlugin({
  http(app, ctx) {
    app.post('/api/my-plugin/reset', ctx.requireAdmin, (_req, res) => res.json({ reset: true }))
  },
})
```

Ein Plugin, das das Token auf anderem Weg entgegennimmt, etwa als Passwort einer Anmeldung, prüft es mit `ctx.adminToken.matches(candidate)`. `ctx.adminToken.configured` sagt, ob der Server eines hat. Das Token selbst bekommt das Plugin nie zu sehen.

Ein Hook, der eine Exception wirft, wird geloggt und für dieses Plugin abgeschaltet, und das Spiel läuft weiter.
