Der Spielserver stellt unter `/admin/` ein Admin-Panel bereit. Es ist ein Layout mit Seitenleiste, und du meldest dich mit dem [Admin-Token](/de/netzwerk/server#admin-token) des Servers an:

```
http://localhost:8050/admin/
```

Die Engine fügt drei Seiten hinzu, in der Seitenleiste unter **Server**:

- **Overview**: Laufzeit, Spieler, Entities und Physikkörper. Darunter die Laufzeitumgebung (Versionen von Engine, Three.js, Rapier und Node.js, Modus und Plattform), der Szenengraph des Servers (Objekte, Meshes, Dreiecke, Lichter und die häufigsten Objekttypen) und seine Physikwelt (Körper nach Typ, schlafende Körper, Collider, Schwerkraft und Zeitschritt). Am Ende steht eine Kachel für jede andere Seite des Panels.
- **Routes**: jeder HTTP-Endpunkt des Servers mit Methode, Pfad, Herkunft, was er tut und wer ihn aufrufen darf. Das ist dieselbe Liste wie im Routes-Tab des [Dashboards](/de/werkzeuge/monitoring#routes).
- **Plugins**: die Plugins in `mavonengine.json` mit ihrer Version, ob sie auf dem Server laufen und welches das Datenbank-, Auth- oder Benachrichtigungs-Plugin ist.

Plugins fügen ihre eigenen Seiten unter **Plugins** hinzu:

| Seite | Plugin | |
| --- | --- | --- |
| `/admin/accounts/` | [`@mavonengine/auth`](/de/werkzeuge/auth#admin-panel) | Jeder Account mit seiner Anmeldeart, seinen Sitzungen und ob er online ist. Du kannst ihn durchsuchen und einen Account deaktivieren, aktivieren oder abmelden |
| `/admin/mail/` | [`@mavonengine/mail`](/de/werkzeuge/mail#dev-posteingang) | Der Dev-Posteingang: jede Mail, die das Spiel in der Entwicklung verschickt hat |
| `/admin/monitoring/` | [`@mavonengine/http-monitoring`](/de/werkzeuge/monitoring#browser-dashboard) | Das Spielserver-Dashboard, mit seinen Tabs in der Seitenleiste |

## Anmelden

```bash
MAVONENGINE_ADMIN_TOKEN=… npm start
```

Du kannst auch `adminToken` in den Optionen des Servers setzen. Gib das Token im Anmeldedialog des Browsers als Passwort ein; der Benutzername ist beliebig. Tools können es stattdessen als `Authorization: Bearer <token>` senden.

- Plugins können weitere Personen hereinlassen. [`@mavonengine/http-monitoring`](/de/werkzeuge/monitoring#anmeldung) tut das mit einer htpasswd-Datei, deren Benutzer sich dann am ganzen Panel anmelden.
- Ohne Admin-Token und ohne weitere Anmeldung antwortet das Panel nur auf Anfragen von localhost. In Produktion (`NODE_ENV=production`) bleibt es aus, bis der Server eines davon hat.
- Nach 10 fehlgeschlagenen Anmeldungen wird eine Adresse für 5 Minuten gesperrt.
- Basic Auth sendet das Passwort mit jeder Anfrage, setze also HTTPS vor einen öffentlichen Server.

## Optionen

```typescript
const server = new MyServer(logger, physicsWorld, {
  admin: { path: '/ops' },        // stattdessen unter /ops/ bereitstellen
  // admin: { enabled: false },   // oder ausschalten
})
```

| Option | Standard | |
| --- | --- | --- |
| `admin.enabled` | `true` | Das Panel bereitstellen. In Produktion braucht es zusätzlich ein Admin-Token oder eine Anmeldung |
| `admin.path` | `/admin` | Wo es bereitgestellt wird. Darf nicht `/` sein |

## Eine Seite hinzufügen

Ein Plugin fügt mit `ctx.admin.page()` in seinem `http()`-Hook eine Seite hinzu. Sie erscheint in der Seitenleiste unter **Plugins**, und die Links, die sie angibt, stehen darunter:

```typescript
import { defineServerPlugin } from '@mavonengine/core/Plugins/types'

export default defineServerPlugin({
  http(app, ctx) {
    ctx.admin.page({
      path: 'chat', // /admin/chat/
      label: 'Chat',
      icon: 'chat',
      children: [
        { label: 'Live', href: '#live' }, // ein Anker auf der Seite
        { label: 'Mutes', href: 'mutes', render: () => '<p>…</p>' }, // eine Unterseite, /admin/chat/mutes/
      ],
      render: req => ({
        html: '<div class="adm-page">…</div>',
        styles: [ctx.admin.url('chat/style.css')],
        scripts: [ctx.admin.url('chat/app.js')],
      }),
    })

    // Jede Route unter dem Pfad des Panels liegt schon hinter seiner Anmeldung
    app.get(ctx.admin.url('chat/api/messages'), (_req, res) => res.json({ messages: [] }))
  },
})
```

| Feld | |
| --- | --- |
| `path` | Wo sie unter dem Panel liegt: `chat` → `/admin/chat/` |
| `label` | Ihr Name in der Seitenleiste |
| `icon` | `dashboard`, `activity`, `routes`, `plugin`, `database`, `users`, `logs`, `settings`, `chart`, `mail`, `chat`, `bell` oder `lock`. Alles andere zeigt den ersten Buchstaben des Labels |
| `group` | Die Überschrift in der Seitenleiste, unter der sie steht. Standard `Plugins` |
| `order` | Kleiner steht weiter oben in ihrer Gruppe. Standard 100 |
| `children` | Links, die darunter stehen, solange sie offen ist. Ein `href` ist ein Anker (`#live`), ein Pfad unterhalb der Seite (`mutes`, im Layout bereitgestellt, wenn er ein `render` hat) oder ein absoluter Pfad bzw. eine URL |
| `render(req)` | Gibt das HTML der Seite zurück, oder `{ html, title, styles, scripts, data }`. `data` wird zu `data-*`-Attributen am `<body>` |

- **Escaping:** Das HTML kommt unverändert in das Layout. Escape alles, was von Spielern oder Anfragen stammt, mit `escapeHtml()` aus `@mavonengine/core/Networking/Server/Admin/AdminPanel`.
- **Skripte:** Die Content-Security-Policy der Seite blockiert Inline-`<script>`-Tags und `style`-Attribute, liefere also Skript- und Stylesheet-Dateien aus.
- **Gestaltung:** Die Farben des Layouts sind CSS-Custom-Properties (`--surface`, `--border`, `--primary`, …), und es hat Klassen für Seiten: `adm-page`, `adm-cards`, `adm-card`, `adm-table` und `adm-badge`.
- **Ersetzen:** Eine Seite, die erneut unter demselben Pfad registriert wird, ersetzt die frühere.

Der Rest von `ctx.admin`:

| | |
| --- | --- |
| `ctx.admin.url(path)` | Der absolute Pfad unter dem Panel: `url('chat/api')` → `/admin/chat/api` |
| `ctx.admin.path` | Wo das Panel liegt, ohne abschließenden Schrägstrich |
| `ctx.admin.enabled` | Ob es antwortet |
| `ctx.admin.guard` | Die Anmeldung des Panels als Express-Middleware, für Routen außerhalb seines Pfads |
| `ctx.admin.addLogin((user, password) => …)` | Mehr Personen anmelden lassen als die, die das Token haben, etwa die Benutzer einer htpasswd-Datei. Darf ein Promise zurückgeben |

Auf einem `@mavonengine/core` von vor dem Admin-Panel ist `ctx.admin` undefined. Ein Plugin, das auch dort laufen soll, prüft es also zuerst: `if (ctx.admin) ctx.admin.page(…)`.
