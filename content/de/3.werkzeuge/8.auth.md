`@mavonengine/auth` gibt einem Multiplayer-Spiel Spieler-Accounts. Spieler registrieren sich und melden sich mit Benutzername und Passwort an, und der Spielserver lässt nur Clients mit einer gültigen Sitzung verbinden. Jede Verbindung hat dann eine stabile Identität, dieselbe Account-ID bei jedem erneuten Verbinden, sodass Stummschaltungen, Punktestände und Spielstände pro Spieler statt pro Verbindung gehalten werden können.

```bash
npx @mavonengine/cli install @mavonengine/sqlite
npx @mavonengine/cli install @mavonengine/auth
```

Es hält seine Accounts in der [Datenbank](/de/werkzeuge/datenbank) des Servers und braucht daher ein Datenbank-Plugin wie `@mavonengine/sqlite`. Ohne eines weist es jeden Client mit 503 ab und sagt das im Log.

Um Verbindungen auf andere Weise zu prüfen, schreib ein eigenes Auth-Plugin mit dem [`authorize()`-Hook](/de/werkzeuge/plugins#spieler-authentifizieren).

## Was es tut

- **Accounts** mit Benutzername und Passwort und optional einer E-Mail-Adresse. Benutzernamen haben 3 bis 32 Buchstaben, Ziffern, `_`, `.` oder `-` und sind unabhängig von Groß- und Kleinschreibung eindeutig. Passwörter haben mindestens 8 Zeichen und werden als scrypt-Hashes gespeichert, die in Node eingebaut sind.
- **E-Mail**: optional, unabhängig von Groß- und Kleinschreibung eindeutig. Der Spieler sieht sie in seinem eigenen Account, Admins in der Account-Liste; die Identität einer Verbindung enthält sie nie. Noch wird nichts an sie gesendet: `emailVerifiedAt` bleibt leer, bis ein Mail-Plugin Adressen bestätigen kann.
- **Sitzungen**: Die Anmeldung gibt dem Browser ein zufälliges Token. Der Server speichert nur dessen sha256-Hash, eine geleakte Datenbank enthält also keine funktionierenden Tokens. Eine Sitzung hält 30 Tage ab ihrer letzten Verwendung.
- **Verbindungsprüfung**: Das Spiel verbindet sich mit der Sitzung, und der Server weist einen Client ab, bevor er einen Spieler bekommt: 401 ohne gültige Sitzung, 403 bei einem deaktivierten Account. Ein Client, der hereinkommt, hat `{ id, name, session }` als Identität; `session` ist ein kurzer, nicht geheimer Schlüssel, der die Sitzungen des Accounts unterscheidet.
- **Gäste**, wenn du sie einschaltest: Spieler legen ohne Registrierung los, mit einem eigenen Gast-Account. Siehe [Gast-Accounts](#gast-accounts).
- **Rate-Limit für Anmeldungen**: Nach 10 fehlgeschlagenen Anmeldungen von einer Adresse für einen Benutzernamen wird das 15 Minuten lang abgelehnt. Ein unbekannter Benutzername wird genauso langsam abgelehnt wie ein falsches Passwort, die Antwort verrät also nicht, welche Namen existieren.
- **Admin-API**: Accounts auflisten, deaktivieren, überall abmelden. Deaktivieren oder Abmelden schließt die Spielverbindungen des Accounts sofort.
- **Andere Anmeldewege**: Plugins wie eine Discord- oder GitHub-Anmeldung übergeben ihre Nutzer an dieses Plugin, siehe [Login-Plugins](#login-plugins).

## Optionen

Setze sie unter dem Plugin in `mavonengine.json`. Alle sind optional.

```json
{
  "plugins": {
    "@mavonengine/auth": {
      "options": {
        "sessionDays": 30,
        "registration": true,
        "devGuests": false
      }
    }
  }
}
```

| Option | Standard | |
| --- | --- | --- |
| `path` | `/api/auth` | Wo die Routen liegen |
| `registration` | `true` | Ob Spieler einen Account mit Benutzername und Passwort anlegen können. Abgeschaltet funktionieren nur bestehende Accounts und Login-Plugins |
| `sessionDays` | `30` | Wie lange eine Sitzung ohne Verwendung hält. Jede Verwendung, auch das Verbinden, verlängert sie |
| `guests` | `false` | Spieler als Gäste spielen lassen, siehe [Gast-Accounts](#gast-accounts) |
| `guestDays` | `30` | Wie lange eine Gast-Sitzung ohne Verwendung hält. Ist sie abgelaufen, wird der Gast-Account gelöscht |
| `guestsPerHour` | `20` | Gast-Accounts, die eine Adresse pro Stunde anlegen darf |
| `devGuests` | `false` | Clients ganz ohne Sitzung hereinlassen, ohne Identität, wenn `NODE_ENV` nicht `production` ist. Praktisch, um den Editor ohne Anmeldung zu öffnen. Ein Produktionsserver tut das nie. Nicht dasselbe wie `guests`, deren Gäste Accounts haben |
| `loginAttempts` | `10` | Fehlgeschlagene Anmeldungen pro Adresse und Benutzername, bevor sie eine Zeit lang abgelehnt werden |
| `loginWindowMinutes` | `15` | Wie lange diese fehlgeschlagenen Anmeldungen zählen |

Das Rate-Limit unterscheidet Adressen anhand von `req.ip`. Setz hinter einem Reverse Proxy im `onHttp()` des Servers Express' `trust proxy`, damit das die Adresse des Spielers ist und nicht die des Proxys.

## Im Browser

Das Plugin sendet die Sitzung, wenn sich das Spiel verbindet. Melde den Spieler an, bevor du den [`NetworkManager`](/de/netzwerk/client#authentifizierung) erstellst, und erstelle einen neuen, um dich nach dem An- oder Abmelden erneut zu verbinden:

```typescript
import { AuthRequestError, checkSession, currentAccount, login, logout, register } from '@mavonengine/auth/client'

// Beim Start: Ist die gespeicherte Sitzung noch gültig?
const account = await checkSession()
if (account)
  joinServer()

async function onLoginForm(username: string, password: string) {
  try {
    await login(username, password)
    joinServer()
  }
  catch (err) {
    if (err instanceof AuthRequestError)
      showError(err.message) // "Wrong username or password", "Too many failed logins, …"
  }
}
```

- `register(username, password, email?)`, `login(username, password)` und `playAsGuest()` lösen mit dem Account auf (`{ id, name, email }`, und `guest: true` für einen Gast) und halten die Sitzung in `localStorage`. Sie lehnen mit einem `AuthRequestError` ab, der `status` und Meldung des Servers trägt.
- `logout()` vergisst die Sitzung, auch auf dem Server, wenn er erreichbar ist. Der Server schließt die mit dieser Sitzung aufgebaute Spielverbindung; die anderen Geräte des Spielers bleiben im Spiel.
- `changePassword(current, password)` ändert es und meldet jedes andere Gerät ab, wobei deren Spielverbindungen geschlossen werden.
- `currentAccount()` ist der gespeicherte Account, ohne den Server zu fragen. `checkSession()` fragt ihn und vergisst eine Sitzung, die der Server nicht mehr kennt.
- `window` bekommt ein `mavonengine:auth`-Event (`AUTH_EVENT`) mit dem Account, oder `null`, wann immer sich der Spieler an- oder abmeldet.

Weist der Server die Verbindung ab, löst der `NetworkManager` `connectError` mit dem `status` aus: 401 heißt erneut anmelden.

## Gast-Accounts

Mit `"guests": true` können Spieler ohne Registrierung spielen, neben denen, die sich registriert haben:

```typescript
import { checkSession, playAsGuest } from '@mavonengine/auth/client'

const account = await checkSession() ?? await playAsGuest()
joinServer()
```

- `playAsGuest()` legt einen Gast-Account an, mit einem Namen wie `Guest-4821`, und meldet den Browser darin an. Ein Gast verbindet sich wie jeder Spieler, mit `guest: true` in seiner Identität, das Spiel kann ihn also erkennen: `if (player.identity?.guest) …`, um Gäste etwa aus der Bestenliste herauszuhalten.
- Ein Gast hat eine Account-ID wie alle anderen, Stummschaltungen, Punktestände und Spielstände an `identity.id` funktionieren also auch für Gäste und überdauern ein erneutes Verbinden.
- `register(username, password)` aus dem Browser eines Gastes macht aus dem Gast-Account einen vollwertigen mit derselben ID, der Gast behält also alles, was das Spiel für ihn gespeichert hat. Dasselbe tut ein [Login-Plugin](#login-plugins) mit `linkTo` auf den Account des Gastes.
- Ein Gast-Account hält nur so lange wie seine Sitzung: `guestDays` ohne Spielen, das Leeren des Browser-Speichers oder `logout()`. Danach kann sich niemand mehr darin anmelden, und er wird gelöscht. Sag Gästen, dass sie sich registrieren sollen, um ihren Fortschritt zu behalten, z.B. wenn `currentAccount()?.guest` true ist.
- Das Deaktivieren eines Gast-Accounts stoppt nur diesen Account: Wer auch immer es war, kann einen neuen Gast anlegen. `guestsPerHour` begrenzt, wie viele eine Adresse anlegt. Für ein Spiel, in dem Sperren halten müssen, lass Gäste abgeschaltet.

## Auf dem Server

Core gibt jedem Plugin und dem Spiel die Identität einer Verbindung: `ctx.identity(channel)` in einem Plugin, `player.identity` im Spiel. Hänge alles, was eine Verbindung überdauern soll, an `identity.id`:

```typescript
export default defineServerPlugin({
  onConnection(channel, player, ctx) {
    const id = ctx.identity(channel)?.id
    if (id)
      loadSave(id)
  },
})
```

`auth(server)` aus `@mavonengine/auth/server` verwaltet die Accounts aus dem Code des Spiels:

```typescript
import { auth } from '@mavonengine/auth/server'

await auth(server).disable(accountId) // kann sich nicht anmelden oder verbinden, seine Verbindungen schließen
await auth(server).enable(accountId)
await auth(server).endSessions(accountId) // überall abgemeldet, seine Verbindungen schließen
const account = await auth(server).account(accountId)
```

Mit Accounts bleiben Stummschaltungen im [Chat](/de/werkzeuge/chat#dauer-einer-stummschaltung) am Account des Spielers, und der Players-Tab des [Dashboards](/de/werkzeuge/monitoring#terminal-dashboard) sowie das Network-Panel des Editors zeigen den Account jedes Spielers.

## Routen

| Route | |
| --- | --- |
| `POST /api/auth/register` | `{ username, password, email? }` → 201 `{ token, account, expiresAt }`. Mit der Sitzung eines Gastes gesendet, wird dieser Gast-Account zu diesem. 409 bei vergebenem Namen oder vergebener E-Mail, 400 bei einem unbrauchbaren, 403, wenn `registration` abgeschaltet ist |
| `POST /api/auth/guest` | Mit eingeschaltetem `guests`: legt einen Gast-Account an und meldet ihn an, 201 `{ token, account, expiresAt }`. 403, wenn Gäste abgeschaltet sind, 429 nach `guestsPerHour` von einer Adresse |
| `POST /api/auth/login` | `{ username, password }` → `{ token, account, expiresAt }`. 401 falscher Benutzername oder falsches Passwort, 403 deaktiviert, 429 zu viele Versuche (mit `Retry-After`) |
| `POST /api/auth/logout` | Beendet die als `Authorization: Bearer <token>` gesendete Sitzung und schließt die damit aufgebauten Spielverbindungen. 204 |
| `GET /api/auth/me` | `{ account }` der Sitzung, 401 ohne Sitzung |
| `POST /api/auth/password` | `{ current, password }`, mit der Sitzung. Jede andere Sitzung des Accounts endet. 204 |

Die Admin-Routen verlangen das [Admin-Token](/de/netzwerk/server#admin-token) des Servers wie jede Admin-Route des Servers und antworten ohne Token nur auf dem Rechner des Servers selbst:

| Route | |
| --- | --- |
| `GET /api/auth/accounts` | `{ accounts, total }`, neueste zuerst, mit `?limit=` und `?offset=`. Jeweils mit `email`, `emailVerifiedAt`, `lastLoginAt`, `guest`, `providers` und aktiven `sessions`, nie mit einem Passwort-Hash |
| `POST /api/auth/accounts/:id/disable` | Er kann sich nicht anmelden oder verbinden, seine Sitzungen enden, seine Verbindungen schließen |
| `POST /api/auth/accounts/:id/enable` | Er kann sich wieder anmelden |
| `DELETE /api/auth/accounts/:id/sessions` | Meldet ihn überall ab und schließt seine Verbindungen. `{ ended }` |

Die Tabellen heißen `auth_accounts`, `auth_identities` und `auth_sessions` und erscheinen im [Database-Tab](/de/werkzeuge/monitoring#database) des Dashboards.

## Login-Plugins

Eine Anmeldung über einen anderen Dienst ist ein eigenes Plugin, das den Teil des Dienstes übernimmt, etwa die OAuth-Weiterleitung, und den Nutzer dann an dieses Plugin übergibt:

```typescript
import { auth } from '@mavonengine/auth/server'

app.get('/api/auth/discord/callback', async (req, res) => {
  const user = await discordUserFor(String(req.query.code))
  const session = await auth(ctx.server).signIn('discord', user.id, { name: user.username })
  // Gib session.token an die Seite weiter, die es wie login() speichert
})
```

`signIn(provider, externalId, profile, options)` meldet den mit diesem Nutzer verknüpften Account an und legt einen an, wenn der Nutzer zum ersten Mal gesehen wird.

- Eine `profile.email` wird auf einem Account gespeichert, der keine hat, es sei denn, ein anderer Account hat sie. Übergib `emailVerified: true`, wenn der Anbieter sie geprüft hat.
- Mit `{ linkTo: accountId }` wird ein zum ersten Mal gesehener Nutzer stattdessen mit diesem Account verknüpft, ein Spieler mit Passwort kann sich also auch mit Discord anmelden.
- Es lehnt mit einem `AuthError` ab: 403 bei einem deaktivierten Account, 409, wenn der Nutzer bereits mit einem anderen Account verknüpft ist.

Ein Login-Plugin hat kein eigenes `authorize()`: Dieses Plugin bleibt dasjenige, das Verbindungen prüft, egal wie sich der Spieler angemeldet hat.
