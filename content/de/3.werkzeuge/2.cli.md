`@mavonengine/cli` stellt den Befehl `mavonengine` bereit. Er benötigt **Node 24** oder neuer.

```bash
npm install -D @mavonengine/cli
npx @mavonengine/cli --help
```

## `mavonengine create`

Erstellt ein neues Projekt aus dem Multiplayer-Template, installiert seine Abhängigkeiten und startet es wie `mavonengine dev`.

```bash
npx @mavonengine/cli create my-game
```

Fragt nach einem Namen, wenn keiner angegeben ist. Ein Startbildschirm zeigt jeden Schritt; danach startet das Dev-Skript, das Dashboard übernimmt, sobald der Spielserver antwortet, und das Spiel öffnet sich im Browser. Es ersetzt `@mavonengine/create-bootstrap`, das jetzt dorthin weiterleitet.

| Option | Standard | |
| --- | --- | --- |
| `--cwd <dir>` | aktuelles Verzeichnis | Wo das Projektverzeichnis erstellt wird |
| `--no-dashboard` | | Fortschritt ausgeben, statt das Dashboard anzuzeigen |
| `--port <port>` | `8050` | HTTP-Port des Spielservers für das Dashboard |
| `--theme <name>` | `dark` | Dashboard-Theme |
| `--transparent` | | Einen transparenten Terminal-Hintergrund durchscheinen lassen |
| `--no-open` | | Das Spiel nicht im Browser öffnen, sobald der Server läuft |

## `mavonengine dev`

Führt das Dev-Skript des Projekts aus, in dem du dich befindest, und zeigt das [Dashboard](/de/werkzeuge/monitoring) dafür an. Beim Multiplayer-Template startet das Spielserver und Client gemeinsam; sein `npm run dev` ist `mavonengine dev`.

```bash
npx @mavonengine/cli dev

# Von woanders aus
npx @mavonengine/cli dev --cwd path/to/my-game
```

- Führt das `dev:server`-Skript des Projekts aus, oder `dev`, wenn es keines gibt.
- Der Projekt-Root ist die nächste `package.json` aufwärts, die von `@mavonengine/core` abhängt und ein `dev`-Skript hat — es funktioniert also auch aus `client/` oder `server/` heraus.
- Der Paketmanager wird anhand der Lockfile erkannt (`npm`, `pnpm`, `yarn` oder `bun`).
- Sobald der Server läuft, öffnet sich das Spiel im Browser; `o` öffnet es erneut. `q` oder `Ctrl-C` beendet das Dev-Skript und alles, was es gestartet hat.

Nimmt dieselben Optionen wie `create`.

## `mavonengine install`

Installiert Pakete mit dem Paketmanager des Projekts. Für jedes Paket, das ein MavonEngine-[Plugin](/de/werkzeuge/plugins) ist, zeigt es an, wo das Plugin läuft und welche Prefabs es mitbringt, und fragt, ob es zu `mavonengine.json` hinzugefügt werden soll.

```bash
npx @mavonengine/cli install @mavonengine/http-monitoring

# Alles, was dein Paketmanager akzeptiert
npx @mavonengine/cli install @acme/forest@^2 file:../my-plugin --yes
```

| Option | Standard | |
| --- | --- | --- |
| `--cwd <dir>` | aktuelles Verzeichnis | Wo die Suche nach dem Projekt beginnt |
| `-y`, `--yes` | | Plugins ohne Nachfrage zu `mavonengine.json` hinzufügen |
| `--no-register` | | Nur installieren |

## `mavonengine build`

Führt das `build`-Skript des Projekts aus und listet dann auf, was jedes Plugin in das Release gelegt hat. Kopiert werden nur die geteilten Plugin-Assets und die der Prefabs, die in `mavonengine.json` aufgeführt sind — ein Release liefert oder lädt also nie eine Datei, die es nicht verwendet.

```bash
npx @mavonengine/cli build
```

## `mavonengine dashboard`

Ein Live-Terminal-Dashboard für einen laufenden Spielserver, siehe [Monitoring](/de/werkzeuge/monitoring).

```bash
npx @mavonengine/cli dashboard
npx @mavonengine/cli dashboard --sim   # simulierte Daten, kein Server nötig
```

## `mavonengine mcp`

Ein Model-Context-Protocol-Server für KI-Assistenten, siehe [KI-Assistenten](/de/werkzeuge/ki-assistenten).
