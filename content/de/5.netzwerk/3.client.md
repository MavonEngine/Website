`NetworkManager` verwaltet die client-seitige WebRTC-Verbindung zum Server über [geckos.io](https://github.com/geckosio/geckos.io).

## Instanz erstellen und abrufen

Leite davon mit geckos.io-Client-Optionen ab. Wenn der Spielserver den Client ausliefert, verbinde dich mit dem eigenen Origin und Port der Seite, so wie es das Multiplayer-Template macht:

```typescript
import BaseNetworkManager from '@mavonengine/core/Networking/Client/NetworkManager'

export default class NetworkManager extends BaseNetworkManager {
  constructor() {
    super({
      // @ts-expect-error null verwendet den eigenen Port der Seite
      port: null,
      url: '/socket',
    })
  }
}
```

`NetworkManager` ist ein Singleton:

```typescript
const network = NetworkManager.getInstance()

// Wird auch am Spiel gesetzt, für Dev-Tools
Game.instance().network
```

## Eigenschaften

| Eigenschaft | Typ | Beschreibung |
|----------|------|-------------|
| `socket` | `geckos.io socket` | Der zugrunde liegende WebRTC-Socket |
| `ping` | `number` | Aktuelle Round-Trip-Latenz in Millisekunden |
| `connected` | `boolean` | Ob der Client mit dem Server verbunden ist |
| `editorMode` | `boolean` | Ob dieser Client den Editor ausführt und daher auf dem Server kein Spieler ist |

## Befehle an den Server senden

Sende Befehle über `sendCommand`. Es vergibt die nächste Sequenz-ID und behält den Befehl für das erneute Abspielen in einer lokalen Warteschlange:

```typescript
network.sendCommand({
  type: ClientCommand.CL_MOVE,
  keys: [...input.keysPressed],
  yaw,
})
```

## Reconciliation

Der Server sendet die `lastProcessedSequenceId` jedes Spielers im Zustandsabgleich mit. Verwirf die Befehle, die der Server bereits angewendet hat; die in der Warteschlange verbleibenden sind diejenigen, die der Server noch nicht gesehen hat und die du auf Basis der Server-Position erneut abspielen kannst:

```typescript
network.dropCommandsAtSequenceId(player.lastProcessedSequenceId)
```

## Zustand vom Server empfangen

Lausche auf dem Socket, sobald die Verbindung steht, z.B. in `onConnect()`:

```typescript
protected override onConnect() {
  super.onConnect()

  this.socket.on(ServerCommand.SV_STATE, (data) => {
    // Server-Zustand auf lokale Entities anwenden, siehe Zustandsabgleich
  })
}
```

## Editor-Modus

Wenn der [Level-Editor](/de/kernkonzepte/level-editor) startet, bleibt die Verbindung offen und der Client meldet sich als Editor an. Der Server entfernt dann seinen Spieler und sendet ihm die ganze Welt, sodass andere Spieler während des Bearbeitens weiter angezeigt werden.

## Verbindungs-Events

Überschreibe `onConnect()`, `onDisconnect()` und `onPong()` in deiner Unterklasse, um auf die Verbindung zu reagieren. `onConnect()` muss `super.onConnect()` aufrufen, das die Ping-Prüfungen startet. `NetworkManager` erweitert `EventEmitter`, du kannst also per `trigger()` weitergeben, was du empfängst, damit der Rest deines Spiels darauf lauschen kann.
