`NetworkManager` handles the client-side WebRTC connection to the server via [geckos.io](https://github.com/geckosio/geckos.io).

## Creating and getting the instance

Subclass it with geckos.io client options. When the game server serves the client, connect to the page's own origin and port, like the multiplayer template does:

```typescript
import BaseNetworkManager from '@mavonengine/core/Networking/Client/NetworkManager'

export default class NetworkManager extends BaseNetworkManager {
  constructor() {
    super({
      // @ts-expect-error null uses the page's own port
      port: null,
      url: '/socket',
    })
  }
}
```

`NetworkManager` is a singleton:

```typescript
const network = NetworkManager.getInstance()

// Also set on the game, for dev tools
Game.instance().network
```

## Properties

| Property | Type | Description |
|----------|------|-------------|
| `socket` | `geckos.io socket` | The underlying WebRTC socket |
| `ping` | `number` | Current round-trip latency in milliseconds |
| `connected` | `boolean` | Whether the client is connected to the server |
| `editorMode` | `boolean` | Whether this client runs the editor, and so is no player on the server |

## Sending commands to the server

Send commands through `sendCommand`. It assigns the next sequence id and keeps the command in a local queue for replay:

```typescript
network.sendCommand({
  type: ClientCommand.CL_MOVE,
  keys: [...input.keysPressed],
  yaw,
})
```

## Reconciliation

The server sends each player's `lastProcessedSequenceId` in the state sync. Drop the commands the server has already applied; the ones left in the queue are those the server hasn't seen yet, which you can replay on top of the server's position:

```typescript
network.dropCommandsAtSequenceId(player.lastProcessedSequenceId)
```

## Receiving state from the server

Listen on the socket once connected, e.g. in `onConnect()`:

```typescript
protected override onConnect() {
  super.onConnect()

  this.socket.on(ServerCommand.SV_STATE, (data) => {
    // Apply server state to local entities, see State Sync
  })
}
```

## Editor mode

When the [level editor](/core-concepts/level-editor) boots, the connection stays open and the client announces itself as an editor. The server then removes its player and sends it the whole world, so other players keep showing while you edit.

## Connection events

Override `onConnect()`, `onDisconnect()` and `onPong()` in your subclass to react to the connection. `onConnect()` must call `super.onConnect()`, which starts the ping checks. `NetworkManager` extends `EventEmitter`, so you can `trigger()` what you receive for the rest of your game to listen to.
